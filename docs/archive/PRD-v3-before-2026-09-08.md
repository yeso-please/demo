> 랭킹 없는 지도에서 발견하고, 실제 하루 동선으로 편집·저장할 수 있는 국내 여행 웹 서비스

> **기준일** 2026.09.06

>
> **상태** 구현 현황 동기화본. 구현 사실과 향후 계획을 분리한다.

## 0. 문서 읽는 법

| 상태 | 의미 |
|---|---|
| **구현** | 현재 코드에 사용자 경로와 저장·조회 로직이 존재한다. |
| **부분 구현** | 화면이나 규칙은 있으나 데이터·품질·연결이 제한적이다. |
| **보조/레거시** | 실행 가능하지만 현재 핵심 사용자 흐름은 아니다. |
| **미구현** | 아이디어 또는 설계만 있고 현재 코드에는 없다. |

문서와 코드가 다르면 코드가 현재 사실이다. 특히 **AI, 학습, 추천 정확도, 사용자 행동 개선**은
실제 구현과 측정 결과가 있을 때만 완료로 표시한다.

## 1. 제품 요약

### 1.1 현재 제품 한 줄 정의

> 사용자가 과거 여행을 줄글로 남기면, 규칙 기반으로 그 글의 경험 태그를 읽고,
> 아직 방문하지 않은 지역의 **실재하는 TourAPI 공식 코스** 중 취향이 가까운 후보를 지도에 켜 준다.
> 사용자는 공식 코스나 자동 조립 코스를 편집·저장하고, 다녀온 뒤 같은 다이어리에 기록을 남긴다.

### 1.2 현재 핵심 루프

```text
초대장 → 여행 다이어리 작성 → 경험 태그 읽기·수정
      → 지도에서 미방문 지역의 공식 코스 3개 발견
      → 지역과 코스의 사진·경유지·데이터 상태 확인
      → 코스 편집·로그인 후 저장 → 실제 도로 동선 확인
      → [다녀왔어요] 다이어리 → 다음 취향 계산에 반영
```

### 1.3 현재 제품이 하는 것과 하지 않는 것

| 구분 | 현재 사실 |
|---|---|
| 발견 | 전국 250개 시군구를 동일한 지도 진입점으로 제공하고 인기순·별점순을 표시하지 않는다. |
| 개인화 | 다이어리의 단어, 만족도, 방문 지역을 12개 경험 태그 벡터로 계산한다. **학습 모델이 아니다.** |
| 추천 단위 | 다이어리 기반 발견에서는 경유지가 있는 TourAPI 공식 코스를 기준으로 지역을 고른다. |
| 실행 | 공식 코스 또는 규칙 기반 자동 코스를 수정·저장하고 카카오 도로 경로를 확인한다. |
| 생성형 AI | 별도 여행 상담에서 Gemini를 사용하며 추천 ID는 DB에서 재검증한다. |
| 무작위 추천 | `/api/recommend`는 입력한 취향·기분·자유문을 추천에 사용하지 않고 지역 하나를 무작위 반환한다. |
| 학습·임베딩 | Region/Traveler/Course 임베딩, 파인튜닝, 리랭커, Contextual Bandit은 미구현이다. |
| 행동 분석 | 추천 노출부터 저장·방문까지 잇는 impression/event 스키마는 미구현이다. |

## 2. 문제 정의와 검증 상태

### 2.1 해결하려는 사용자 문제

> 국내 여행 의향은 있지만 목적지는 정하지 못한 사용자가 검색어와 인기순 결과를 반복해서 보다가
> 익숙한 지역만 후보로 남기는 상황에서, 자신의 과거 경험과 연결된 낯선 지역을 발견하고
> 별도 조사 없이 하루 코스의 형태까지 확인할 수 있게 한다.

### 2.2 아직 증명되지 않은 전제

- 사용자가 실제로 “새로운 국내 지역을 찾기 어렵다”는 문제를 반복해서 겪는지 검증되지 않았다.
- 축제 검색, 포털, 대한민국 구석구석, 범용 AI보다 더 나은 선택을 만드는지 검증되지 않았다.
- 랭킹 없는 지도가 익숙한 지역 편향을 줄이는지 검증되지 않았다.
- 다이어리를 먼저 써야 하는 비용보다 추천과 기록의 보상이 큰지 검증되지 않았다.
- 코스 저장이 실제 방문 의도를 뜻하는지, 실제 방문으로 이어지는지 측정되지 않았다.

따라서 현재 제품은 **문제 해결이 검증된 서비스가 아니라 검증 가능한 프로토타입**으로 표현한다.

### 2.3 차별성 주장 범위

현재 차별성은 “AI 여행 추천”이나 “숨은 지역 소개”가 아니다. 방어 가능한 조합은 다음 세 가지다.

1. 여행 조건 설문 대신 **사용자가 직접 쓴 과거 여행 글**을 추천 입력으로 쓴다.
2. 추천 결과를 목록이 아니라 **전국 지도에 불이 켜지는 장면**으로 보여준다.
3. 발견을 정보 카드에서 끝내지 않고 **편집 가능한 코스와 실제 도로 동선**으로 잇는다.

이 조합도 사용자 비교 실험 전에는 차별성이 입증됐다고 주장하지 않는다.

### 2.4 지역 활성화에 관한 경계

지역 상권 발전은 기대 효과이지 현재 사용자가 앱을 켜는 직접 이유로 검증되지 않았다.
실제 방문·소비 데이터가 생기기 전까지 “지역 경제를 살린다”, “비유명 지역 방문을 늘린다”를 성과로 사용하지 않는다.
현재 1차 수혜자는 여행자이며 지자체·상인은 후속 이해관계자다.

## 3. 핵심 사용자와 사용 상황

### 3.1 우선 사용자 가설

- 국내 여행 경험이 이미 몇 차례 있는 20~30대 1~2인 여행자
- 목적지가 정해지지 않은 주말·연휴 여행을 준비하는 사람
- 새로운 곳은 원하지만 여러 앱과 블로그를 비교해 하루 동선을 짤 시간이 부족한 사람
- 자신의 여행 기록을 짧은 글로 남기는 데 거부감이 적은 사람

이 정의는 아직 인터뷰로 확정되지 않은 가설이다.

### 3.2 핵심 Job-to-be-Done

> “이번에 어디로 갈지 모르겠을 때, 내가 전에 좋아했던 여행의 결을 출발점으로
> 처음 보는 지역 하나를 납득하고, 오늘 실행할 수 있는 코스까지 빠르게 만들고 싶다.”

### 3.3 주요 사용 상황

| 상황 | 사용자가 원하는 결과 | 현재 지원 |
|---|---|---|
| 목적지 없이 탐색 | 내 취향과 이어지는 새로운 지역 후보 | 다이어리 기반 공식 코스 후보 3개 |
| 특정 지역 검토 | 무엇이 있고 어떤 코스가 가능한지 판단 | 지역 상세·관광지·먹거리·공식/간이 코스 |
| 가까운 곳 탐색 | 거리 안에서 취향에 맞는 반나절 후보 | `/nearby` |
| 동행자와 결정 | 후보별 의견을 모아 하나를 확정 | 공유 방과 비로그인 반응 |
| 여행 준비 | 경유지를 바꾸고 저장해 실제 동선을 확인 | 코스 편집·저장·카카오 경로 |
| 여행 후 | 다녀온 경험을 기록하고 다음 추천에 반영 | `[다녀왔어요]` 다이어리 |

## 4. 제품 원칙

1. **지도는 발견의 무대다.** 모든 시군구는 클릭 가능하며 화면에 인기 순위를 표시하지 않는다.
2. **AI라는 이름보다 실제 동작을 정확히 말한다.** 규칙 기반, 무작위, 생성형 AI를 구분한다.
3. **입력은 사용자에게도 남아야 한다.** 다이어리는 추천 설문이면서 개인 여행 기록이다.
4. **추천 이유와 코스 내용은 연결되어야 한다.** 근거로 든 경험이 실제 경유지에서 확인되어야 한다.
5. **없는 데이터는 채우지 않는다.** 설명·운영시간·거리·좌표가 없으면 누락 또는 추정임을 표시한다.
6. **공식 데이터와 자동 조립을 구분한다.** TourAPI 공식 코스와 규칙 기반 코스를 혼동시키지 않는다.
7. **발견은 실행으로 끝난다.** 지역 정보 다음에는 코스 선택·편집·저장·길찾기가 있어야 한다.
8. **추천은 랭킹을 숨기는 행위가 아니다.** 내부 점수와 후보 제외 규칙의 편향도 검토한다.
9. **한 편으로도 결과를 준다.** 다이어리 편 수를 근거 없이 강제하지 않는다.
10. **기록과 후기를 분리하지 않는다.** 과거 여행과 추천 후 여행을 `Diary` 하나로 잇는다.
11. **검증되지 않은 효과를 성과처럼 쓰지 않는다.** 저장, 방문, 지역 소비를 각각 측정한다.

## 5. 현재 사용자 경험

### 5.1 첫 방문과 다이어리

```text
GET / → 여행 초대장
  ├─ 로그인·회원가입
  └─ 가입 없이 여행 한 편 적기 → /onboarding/visits

지역 검색/지도 선택 → 여행 시기 → 줄글 → 읽힌 경험 밑줄
→ 잘못 읽힌 태그 제외 → 만족도 → 저장 → /map
```

- 비로그인 입력은 HTTP 세션에 최대 30편까지 보관한다.
- 로그인 입력은 `Diary`에 저장하고 회원가입 시 세션 다이어리를 계정에 옮긴다.
- 같은 시군구 중복과 존재하지 않는 시군구 코드는 저장 전에 제거한다.

### 5.2 지도 발견

- D3 Geo와 TopoJSON으로 전국 250개 시군구 폴리곤을 렌더한다.
- 마우스, 키보드, 지역 검색, 무작위 발견으로 지역을 열 수 있다.
- 다이어리가 있으면 `/api/onboarding/candidates`에서 최대 3개의 후보를 가져온다.
- 발견 카드에는 지역, 공식 코스, 사진, 경유지, 일치 태그와 추천 이유가 표시된다.
- 카드를 선택하면 해당 지역이 빛나고 코스 미리보기 패널이 열린다.
- 후보가 2개 이상이면 공유 방으로 보내 동행자에게 물어볼 수 있다.

### 5.3 지역 판단

`/region?sigCd=...`는 관광지·음식점·착한가격업소·특산물 수, 대표 랜드마크, 확보된 설명,
TourAPI 공식 코스, 공식 코스가 없을 때의 간이 코스, 자동 하루 코스 진입과 목적지 길찾기를 제공한다.

지역 단위 서사 원문은 TourAPI에 없다. 현재 “지역의 여행 장면”은 주민 이야기나 생활문화 아카이브가 아니라
**관광지·먹거리·특산물 데이터의 요약**이다.

### 5.4 공식 코스와 사진 여정

`/course?sigCd=...&courseId=...`는 다음을 제공한다.

- TourAPI 공식 출처, 테마, 경유지 수와 코스 소개문
- 미수집 소개문의 동기화 대기 상태
- 경유지 순서를 유지한 최대 8장의 사진 여정과 자동 이동
- 좌표 매칭·상세 수집·운영시간 확보 개수
- 원천 총거리 값이 있을 때만 거리 표시
- 각 경유지의 사진·설명·주소·좌표

사진은 장식이 아니라 코스를 “가 보고 싶은 하루”로 판단하게 하는 핵심 정보다.

### 5.5 자동 하루·반나절 코스

`DayPlanService`는 외부 AI 호출 없이 규칙으로 코스를 조립한다.

```text
하루: 오전 관광지 → 점심 식당 → 오후 관광지 → 저녁 식당
반나절: 걷기 좋은 장소 → 가까운 카페/한 끼 → 가능한 경우 인근 장소
```

- 숙박·쇼핑·기간 검증이 없는 축제는 자동 코스 경유지에서 제외한다.
- 같은 지역과 `variant` 값에는 같은 조합을 반환한다.
- 긴 구간은 비우며 최소 두 곳이 있어야 코스로 인정한다.
- 편집 중 이동 시간과 거리는 직선거리 기반 추정이다.
- 좌표 없는 착한가격업소는 최대 한 곳 포함될 수 있고 이동 추정에서는 빠진다.

### 5.6 코스 편집·저장·도로 경로

- 관광지, 먹거리, 착한 식당, 특산물을 담고 삭제하거나 순서를 바꾼다.
- 장소가 없으면 저장할 수 없고, 한 곳뿐이면 “한 곳 더 담으면 동선이 그려진다”고 안내한다.
- 비로그인도 편집할 수 있으나 저장에는 로그인이 필요하다. 초안은 `sessionStorage`에 보관한다.
- 저장 후 카카오모빌리티 Directions API로 도로 거리·시간·경로를 한 번 계산해 캐시한다.
- 좌표가 두 곳 미만이거나 API 키·응답이 없으면 이유를 표시한다.

### 5.7 여행 후 기록과 공유

- `/my/courses`의 `[다녀왔어요]`는 코스 지역을 선택한 상태로 다이어리를 연다.
- 본인 코스일 때만 새 편에 `savedCourseId`가 붙는다.
- 공개 다이어리는 `/reviews`와 `/diary/{id}`에서 읽을 수 있다.
- `/u/{nickname}`은 공개 편만 사용해 방문 지역과 상위 태그를 지도에 표시한다.
- 기존 `Review` 후기 경로도 호환용으로 남아 있으나 중심 기록은 `Diary`다.

### 5.8 보조 흐름

| 흐름 | 현재 동작 | 위치 |
|---|---|---|
| 근처 추천 | 거리 상한으로 먼저 제한하고 다이어리가 있으면 태그 유사도로 정렬 | `/nearby` |
| 함께 고르기 | 링크 방, 비로그인 닉네임 반응·댓글, 방장 확정 | `/trips/{code}` |
| 여행 상담 | Gemini가 DB 목록 안에서 제안하고 지역·코스 ID를 재검증 | `/chat` |
| 여행 MBTI | 프로필 뱃지와 Gemini 상담 문맥에 사용 | `/onboarding` |
| 무작위 지역 | 관광지가 있는 시군구 하나를 무작위 반환 | `/api/recommend` |

여행 MBTI와 무작위 추천은 실행 가능하지만 다이어리 기반 핵심 루프와는 별도다.

## 7. 현재 추천 로직

### 7.1 표현과 계산

현재 표현은 자연, 바다, 산, 산책, 골목, 역사, 시장, 로컬음식, 카페, 휴식, 실내, 체험의 12개 축이다.

1. 지역 관광지의 이름·설명·유형에서 태그 출현 횟수를 센다.
2. 전국에서 흔한 태그의 영향은 IDF로 낮추고 벡터를 정규화한다.
3. 다이어리 지역 벡터에 만족도(`1.0`, `0.7`, `0.2`, `-0.5`)를 적용한다.
4. 사용자가 승인한 글 태그에는 1.5배를 적용하며 반복은 최대 3회까지만 반영한다.
5. 합산 뒤 음수를 0으로 자르고 사용자 취향 벡터를 정규화한다.

### 7.2 발견 후보 조건

현재 다이어리 기반 발견은 다음을 모두 만족해야 한다.

1. 미방문 지역
2. 관광지 3곳 이상
3. 경유지가 있고 화면에 쓸 수 있는 TourAPI 공식 코스 존재
4. 사용자 취향과 공식 코스의 코사인 유사도 0.45 이상
5. 최고 유사도의 92% 범위 안에 있는 후보

같은 대표 태그가 반복되면 페널티를 주고 최대 3개를 고른다. 점수는 화면에 표시하지 않지만
**내부 유사도와 필터가 노출을 결정한다.**

### 7.3 명확한 한계

- 12개 태그는 지역 간 경험 차이를 세밀하게 구분하지 못한다.
- 상세 설명 확보율에 따라 지역 벡터 품질이 달라진다.
- 공식 코스 경유지 커버리지가 낮아 발견 지역도 소수 지역에 편중된다.
- 서비스 노출 횟수를 보정하는 Exposure Balance는 없다.
- 무작위 API의 `styles`, `mood`, `freeText`는 추천에 사용되지 않는다.
- 사용자 행동으로 추천이 학습되거나 개인별 모델이 갱신되지 않는다.

## 10. 로그인·권한·개인정보

### 10.1 로그인 없이 가능한 일

초대장, 다이어리 세션 작성, 지도·지역·코스 탐색과 편집, 근처 탐색, 공개 글·지도 열람,
공유 방 참여, 여행 상담과 추천 API 호출.

### 10.2 로그인이 필요한 일

코스 저장·저장 완료·내 코스, 프로필·비밀번호 변경, 이전 `Review` 후기 작성.

### 10.3 현재 개인정보 상태

- 로그인 전 다이어리는 서버 세션, 코스 초안은 브라우저 `sessionStorage`에 둔다.
- 공개 다이어리만 피드와 공개 지도에 포함한다.
- 저장 코스 조회와 다이어리 연결에서 소유자를 검사한다.
- 추천 학습용 행동 로그와 동의·삭제 흐름은 아직 없다.

## 11. 성공 기준과 검증 계획

### 11.1 North Star 후보

> **추천 후 실제 방문 증명률**
>
> 다이어리 기반 후보를 본 사용자 중 추천 코스를 저장하고 이후 `[다녀왔어요]` 다이어리까지 남긴 비율

`Diary.savedCourseId`로 결과는 확인할 수 있지만 추천 노출 이벤트가 없어 현재 정확한 분모를 계산할 수 없다.

### 11.2 우선 검증 질문

1. 사용자는 조건 칩보다 과거 여행 글을 쓰는 방식을 받아들이는가?
2. 다이어리 기반 후보가 무작위·포털·범용 AI보다 더 가고 싶게 만드는가?
3. 지도에서 불이 켜지는 장면이 목록보다 예상 밖 지역 탐색을 늘리는가?
4. 사진 여정과 데이터 공백 표시가 공식 코스의 신뢰와 저장 의도를 높이는가?
5. 자동 조립 코스가 지역 정보만 본 경우보다 실행 의도를 높이는가?

### 11.3 로그 없이 가능한 첫 실험

- 10~15명에게 최근 국내 여행지 결정 과정을 인터뷰한다.
- 같은 사람에게 무작위, 기존 포털/범용 AI, 여행페이지 후보를 순서를 섞어 보여준다.
- `가고 싶은 정도`, `이유 납득도`, `새로움`, `실제 저장 선택`을 1~5점으로 받는다.
- 지도형과 목록형에서 처음 연 지역 수와 선택 시간을 기록한다.
- 진행자 도움 없이 다이어리→지도→코스 흐름을 완료하는지 관찰한다.

### 11.4 이벤트 도입 후 퍼널

```text
다이어리 저장 → 후보 실제 노출 → 코스 미리보기 → 상세
→ 코스 편집 → 저장 → 길찾기·재열람 → 다녀왔어요
```

각 이벤트는 세션/사용자, 추천 요청, 지역·코스, 추천 로직 버전과 연결한다.
지도에 그려졌지만 사용자가 보지 않은 지역은 부정 반응으로 취급하지 않는다.

## 14. 다음 개발 우선순위

### P0 — 측정 가능하게 만들기

1. 추천 요청·후보 노출·미리보기·저장·다녀왔어요를 연결하는 최소 이벤트 스키마
2. 다이어리→지도→코스 전 흐름의 무도움 사용성 테스트
3. 공식 코스와 자동 조립 후보의 동일 평가 화면 비교
4. `/api/recommend`와 숨겨진 AI 모달을 제거하거나 “무작위 발견”으로 정확히 명명
5. PRD·SCREENS·DATA의 구현 상태와 숫자 기준일 동기화

### P1 — 가고 싶은 이유 강화

1. 공식 코스 사진 여정의 모바일·저속 네트워크 상태 개선
2. 관광지 상세 배치 완료 후 코스별 설명 확보율 재측정
3. 추천 태그와 실제 경유지의 대응 근거 표시
4. 다이어리 사진 업로드와 공개 지도·피드 연결
5. 생활문화 원천이 확보된 지역만 사람·가게·이야기 중심 장면 실험

### P2 — 데이터가 생긴 뒤 추천 고도화

- 고정 평가셋에서 BM25, 12태그, 사전학습 임베딩을 같은 후보 풀로 비교
- 사전학습 임베딩이 사람 평가에서 baseline을 넘을 때만 채택
- 실제 노출·선택·방문 데이터가 충분해진 뒤 리랭커와 탐색/활용 정책 검토
- 사용자·시간 단위 대조 실험 없이 장기 효과를 주장하지 않음

## 15. 대회 발표에서 가능한 주장

### 15.1 지금 증명 가능한 것

- 전국 250개 시군구를 하나의 SIG_CD 축으로 연결한 탐색 화면이 동작한다.
- 여행 글의 단어 위치를 찾아 밑줄과 수정 가능한 태그로 보여준다.
- 방문 지역과 만족도를 반영해 미방문 지역의 공식 코스 후보를 계산한다.
- 공식 코스의 사진·경유지·상세·운영시간 데이터 공백을 숨기지 않는다.
- 지역 데이터로 자동 하루·반나절 코스를 만들고 사용자가 수정할 수 있다.
- 저장 코스의 실제 도로 경로·거리·시간을 계산하고 재사용한다.
- 추천 코스로 다녀온 기록을 `savedCourseId`로 연결한다.

### 15.2 지금 주장하면 안 되는 것

- AI가 사용자 취향을 학습한다.
- 추천 정확도가 기존 서비스보다 높다.
- 모든 시군구가 개인화 추천 후보로 동등하게 노출된다.
- 숨은 지역 방문이나 지역 상권 매출을 늘렸다.
- 사용자 로그로 모델을 고도화했다.
- 축제가 추천과 코스에 반영된다.

### 15.3 권장 데모 순서

1. 과거 여행 한 편을 작성한다.
2. 읽힌 단어에 밑줄이 생기고 틀린 태그를 뺄 수 있음을 보여준다.
3. 같은 지도에서 예상하지 못한 지역의 불이 켜지는 장면을 보여준다.
4. 후보 공식 코스의 사진 여정과 데이터 확보 범위를 확인한다.
5. 코스를 수정하고 한 곳/두 곳 이상의 지도 안내 차이를 보여준다.
6. 로그인 후 저장해 실제 도로 동선·거리·시간을 확인한다.
7. `[다녀왔어요]`로 기록이 다음 추천 입력이 되는 루프를 닫는다.

기술 포인트는 “AI” 라벨이 아니라 **텍스트 근거 추출, 추천 근거와 코스의 연결,
결측을 포함한 데이터 신뢰 표현, 실행 동선과 여행 후 기록의 폐루프**다.

| 다이어리 기반 발견 | 취향과 가까운 공식 코스 보유 미방문 지역을 고르는 현재 로직 |
| 공식 코스 | TourAPI의 `TravelCourse`와 순서 있는 `CoursePoint` |
| 자동 조립 코스 | `DayPlanService`가 지역 데이터를 규칙으로 잇는 코스 |

| 랭킹 없음 | 점수 순위를 표시하지 않는 UI 원칙. 내부 선택 규칙이 없다는 뜻은 아님 |
