# 숨은여행 — 화면 정의

> 이 문서는 **화면이 무엇을 하는가**만 정의한다. 왜 그렇게 정했는지는 [PRD.md](PRD.md),
> 데이터의 한계는 [DATA.md](DATA.md)에 있다.
> 최종 개정: 2026-08-30 (다이어리 루프 반영)

---

## 0. 이 서비스의 루프

```
        ┌──────────────────── 주 루프 (자주 돈다) ────────────────────┐
        │                                                             │
   기억을 적는다 ──→ 취향이 읽힌다 ──→ 지도에 불이 켜진다 ──→ 어두운 곳이 눈에 밟힌다
        ↑                                    │
        │                                    ↓
        │                            코스를 받는다
        │                                    │
        │                                    ↓
        └──────── 다녀와서 적는다 ←──── 실제로 다녀온다
                       │
              └─── 큰 루프 (가끔 돈다, 대신 결정적) ───┘
                       │
                       ↓
                 다른 사람과 지도를 나눈다
```

**두 루프의 역할이 다르다.**

| | 도는 빈도 | 하는 일 |
|---|---|---|
| 주 루프 | 한 자리에서 여러 번 | 서비스를 살린다. 누구나 과거 여행이 열 곳쯤 있고, 그건 오늘 저녁에 다 쓸 수 있다 |
| 큰 루프 | 1년에 두세 번 | 추천이 맞았다는 **증명**. `Diary.savedCourseId` 가 그 증거다 |

큰 루프에만 기대면 서비스가 1년에 두세 번 돌고 만다. 주 루프가 볼륨을 만들고,
큰 루프가 그 볼륨이 진짜였음을 확인한다.

**다이어리는 입력이자 출력이다.** 온보딩에서 쓰는 '기억'과 다녀와서 쓰는 '기록'은
같은 객체(`Diary`)다. 나누면 후기는 취향으로 안 읽히고 다이어리는 사진도 공유도 없는
반쪽 둘이 된다 — 실제로 그렇게 나뉘어 있었고, 2026-08-30 에 합쳤다.

### 1) `/` 들어오기

| | |
|---|---|

### 2) `/onboarding/visits` 여행 다이어리 ★

이 서비스의 **유일한 입력**이다. 온보딩 전용이 아니라 계속 돌아오는 화면이다.

| | |
|---|---|
| **목적** | 여행을 줄글로 적게 하고, 그 글에서 취향을 읽는다 |
| **진입** | `/`, 헤더 [여행 기록], 지도 배너, 내 지도, 코스 [다녀왔어요] |

**흐름 — 지역이 먼저, 글이 다음**

```
지역 고르기  ──→  쓰기  ──→  읽힌 것 확인  ──→  저장  ──→  목록에 쌓임
  검색 / 지도        줄글      밑줄 + 칩         만족도      [+ 한 편 더]
```

| 단계 | 정의 |
|---|---|
| 지역 고르기 | 이름 검색 또는 "지도에서 고를게요". 지역 없이 글만 쓰는 건 안 된다 — 어디인지 모르면 지도에 불을 못 켠다 |
| 언제 | `"작년 가을"` 처럼 **쓴 그대로**. 날짜 입력을 강요하지 않는다 |
| 본문 | 명조체, 줄높이 2.05. textarea 위에 하이라이트 층을 정확히 겹쳐 **읽힌 단어에 밑줄**을 긋는다 |
| 읽힌 것 | 칩으로 보여주고, **틀린 건 눌러서 뺀다**. 태그를 고르게 하지 않는다 — 고르게 하면 그건 설문이다 |
| 만족도 | 또 가고 싶다 / 좋았다 / 그저 그랬다 / 나와 안 맞았다 |
| 사진 | (예정) 여러 장. '기록'일 때 특히 |
| 편 수 | **강제하지 않는다.** 한 편이면 한 편으로 읽고, 그렇다고 화면이 말한다 |

**규칙**
- 최소 1편이면 결과를 본다. "3편 필요"는 근거 없는 숫자였다(3→6편에서 후보가 계속 절반씩 바뀌었다)
- 화면은 늘 **몇 편으로 읽은 결과인지** 밝힌다
- 비로그인은 세션, 로그인은 DB. 로그인하는 순간 세션의 편들이 옮겨진다

**마침** [지도에 불 켜기] → ③

### 3) `/map` 지도 ★

| | |
|---|---|
| **목적** | 내가 쓴 글이 부른 지역들에 **불이 켜지는 장면** |
| **핵심 원칙** | 랭킹이 없다. 후보는 순위가 아니라 서로 다른 이유로 놓인다 |

**레이아웃**

```
┌─ 헤더 ────────────────────────────────────────────────┐
├───────────────┬──────────────────────┬────────────────┤
│ 당신의 글이   │                      │  (지역 선택 시) │
│ 부른 곳       │      전국 지도       │  지역 패널     │
│               │      250 시군구      │  슬라이드 인   │
│ 사진          │                      │                │
│ 지역명        │   내 지역에 불이     │                │
│ 왜 여기인지   │   켜진다             │                │
│ 태그          │                      │                │
│               │                      │                │
│ [같이 갈 사람 │   [무작위로 발견]    │                │
│  에게 물어보기]│   [지금 나갈 만한 곳] │                │
└───────────────┴──────────────────────┴────────────────┘
                        푸터 없음
```

**푸터를 두지 않는다.** 한국은 세로로 긴 나라라 이 지도는 **높이가 곧 크기**다 —
폭은 아무리 넓어도 그리는 크기를 못 늘린다. 실측(1440×900): 푸터가 있을 때 지도가
537×578, 걷어내니 617×665 로 15% 커졌다.

| 요소 | 정의 |
|---|---|
| 지도 | 250 시군구. 다이어리를 쓴 지역과 추천 지역은 **다른 색**이다 — 한 화면에서 두 의미를 섞지 않는다 |
| 발견 카드 | 사진 + 지역명 + 왜 여기인지 + 태그. 점수는 **안 보여준다**(보여주면 이름만 바뀐 랭킹이다) |
| 빈 상태 | 다이어리가 없으면 "여행 적으러 가기"만 남는다. 다른 걸로 채우지 않는다 |
| 물어보기 | 후보 2곳 이상일 때만. 화면에 보이는 순서 그대로 방으로 넘어간다 |

### 5) `/course` 하루 코스

| | |
|---|---|
| **목적** | "그래서 여기서 뭘 하지"에서 멈추지 않게 한다 |

**구성 (위에서부터)**

| 블록 | 정의 |
|---|---|
| **표지** | 사진 + 지역명 + 이 하루의 결 한 줄. 표를 먼저 보여주면 "갈 만한가"를 따지고, 사진을 먼저 보여주면 "가고 싶은가"를 느낀다 |
| 고른 이유 | 계산된 사실만 |
| 실행 지표 | 이동(추정) · 식비(공시가) · 운영시간 확인 N/M곳. **추정과 실측을 섞어 쓰지 않는다** |
| 동선 지도 | 담은 순서대로 |
| 시간표 | 오전·점심·오후·저녁. 자리마다 사진 · 이름 · **한 줄 설명** · 머무는 시간 |
| 편집 | 왼쪽 후보에서 담고, 순서를 바꾸면 이동 추정이 다시 계산된다 |
| **[다녀왔어요]** | → ② 다이어리(이 코스가 붙은 채로). **큰 루프가 닫히는 지점.** 예전 '후기 쓰기' 자리다 — 후기는 서비스에 남기는 평가지만 다이어리는 내 기록이고 다음 추천을 바꾼다 |

### 7) `/my/discoveries` 내 지도 ★

| | |
|---|---|
| **목적** | 재방문의 이유. 어두운 전국 지도가 내 여행으로 하나씩 켜진다 |
| **표시** | "250곳 중 N곳" · 켜진 지역 · 남은 어둠 |
| **주 행동** | [한 편 더 적기] → ② |
| **공유** | [내 지도 링크 복사] → `/u/{닉네임}` — **공유 단위는 코스가 아니라 내 지도다** |

> 코스를 공유하면 그건 정보다. 지도를 공유하면 그건 사람이다 — "내가 밝힌 37곳".
> 남의 지도를 보면 "이 사람은 바닷가만 다녔네"가 한눈에 보이고, 그게 글을 읽게 만드는 입구가 된다.

**말하지 않는 것**: 몇 편을 써야 한다고 하지 않는다. 한 편으로도 읽고, 더 쓰면 덜 흔들린다는 사실만 알린다.

**공유 버튼은 조건부다** — 로그인했고 공개한 편이 있을 때만 나온다.
비로그인 다이어리는 세션에만 있어 남이 열 수 있는 주소가 없고, 공개편이 없으면 빈 지도가 열린다.

---

### 7-1) `/u/{닉네임}` 남의 지도

| | |
|---|---|
| **목적** | 공유의 도착지. 어두운 전국 위에 그 사람이 다녀온 곳만 켜져 있다 |
| **로그인** | **불필요** — 공유받은 사람은 대개 비로그인이다. 로그인 벽을 세우면 공유가 성립하지 않는다 |
| **구성** | 닉네임 · "250곳 중 N곳" · **결 태그**(많이 쓴 순 5개) · 지도 · 다녀온 곳 목록 |
| **상호작용** | 켜진 곳만 누를 수 있다 → `/diary/{id}`. 안 다녀온 지역은 여기서 할 일이 없다 |
| **보는 사람에게** | [나도 내 지도 만들기] → ② |

**공개한 편만 담는다.** 비공개로 쓴 편은 글도 안 보이고 **지도의 불도 안 켜진다** —
글은 감췄는데 다녀온 사실이 드러나면 감춘 게 아니다.

**지도에 못 붙는 편은 통째로 뺀다.** 남기면 "3곳 밝혔어요"라고 써놓고 불은 2개만 켜져
숫자와 그림이 어긋난다(실제로 그랬다).

### 8) `/my/courses` 담은 코스

저장한 코스 목록. 각 코스에 **[다녀왔어요]** → ②(그 지역이 이미 골라진 채로 열린다).

> 코스에서 들어온 편에만 `savedCourseId` 가 붙는다. 같은 화면에서 다른 지역을 더 적을 수도 있는데,
> 그건 '기억'이지 이 코스의 기록이 아니다. 남의 코스를 내 다이어리에 붙일 수 없도록 소유자를 확인한다.

### 9) `/reviews` 다이어리 피드 · `/diary/{id}` 한 편 읽기

| | |
|---|---|
| **목적** | 남의 여행 글을 읽는다 |
| **단위** | 다이어리 한 편(공개된 것만 최신 50편). 옛 후기도 옮겨져 있어 함께 나온다 |
| **카드 제목** | **코스명이 아니라 지역이다.** 대부분의 편은 코스 없이 쓴 '기억'이라 코스명이 없고, 사람이 기억하는 단위도 지역이다 |
| **사진** | 있는 편에만 띠를 얹는다. 없는 자리에 회색 판을 두면 피드가 빈칸 투성이로 보인다 |
| **코스 뱃지** | 우리 추천으로 다녀와서 쓴 편에 `코스대로 다녀옴` — 같은 피드 안에서 무게가 다른 글이다 |
| **비공개** | 링크를 알아도 남은 못 본다. 작성자에게만 보인다 |
| **(예정)** | 글쓴이의 켜진 지도를 카드에 함께 — 지도가 사람의 얼굴이다 |

> **없는 지역 코드는 저장 단계에서 막는다.** 전북 45→52 코드 변경 때 `52130` 으로 쓴 편이
> 지도에도 피드에도 못 붙는 걸 실제로 겪었다. 조용히 사라지느니 안 받는 편이 낫다.

### 10) `/trips/{code}` 함께 고르기

| | |
|---|---|
| **진입** | 지도 발견 패널의 [같이 갈 사람에게 물어보기] |
| **행동** | 가입 없이 닉네임만으로 좋아요/괜찮아요/패스 + 한마디 → 방장이 확정 |
| **안 하는 것** | **묻지 않은 조건을 적지 않는다.** 예전엔 폼에서 받은 출발지·이동수단을 적었는데, 폼이 없어진 지금 기본값을 채우면 참여자에게는 *방장이 정한 조건*으로 보인다. 방향 딱지('취향을 넓히는 하루')도 같은 이유로 뺐다 |

---

### 11) `/profile` 프로필

활동 지표 순서: **쓴 여행 편 수 · 불 켠 지역 수** → 담은 코스 · 쓴 후기.
이 서비스의 활동은 앞의 둘이 먼저고, 뒤의 둘은 그 결과로 쌓인다.
여행 MBTI는 뱃지로만 남는 **선택 항목**이다.

## 3. 화면에서 걷어낸 것 (이전 기획의 잔재)

| 걷어낸 것 | 이유 |
|---|---|
| `/trip/new`·`/trip/recommendations` 맞춤 여행안 | 조건 폼 → 후보 3안. 다이어리가 같은 일을 한다. 둘을 남기면 어느 쪽이 진짜인지 알 수 없다 |
| `/onboarding/dna` 결과 화면 | 카드와 지도가 곧 결과다. 화면을 넘기면 "내 글이 이 지역을 불렀다"는 연결이 끊긴다 |
| 지도의 '오늘의 숨은 여행지' | 선정 기준이 '수도권 제외 + 관광지 10곳 이상'이었다. 랭킹을 없앤 게 아니라 **다른 랭킹**이었다 |
| `/onboarding` MBTI 12문항 | 묻기만 하고 아무것도 보여주지 못한 채 화면 하나를 더 쓴다. 프로필의 선택 항목으로 내렸다 |
| 지도 화면의 푸터 | 지도의 크기를 15% 깎고 있었다 |
