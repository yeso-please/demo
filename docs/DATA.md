# 데이터 현황과 제약

> 디자인 전에 반드시 읽어주세요.
> **없는 데이터를 전제로 한 디자인은 구현 단계에서 되돌아옵니다.**
> 기준일: 2026-08-13 (재실측) · 수치는 개발 DB 실측값
> ⚠ 관광지 상세 설명은 **선적재 배치가 매일 채우는 중**이라 계속 변합니다 — §3

## 2. 지역 소개글은 **없습니다**

TourAPI(KorService2)에 지역 단위 소개 문구를 주는 오퍼레이션이 없습니다.
`areaCode2` 응답 필드는 `rnum, code, name` 뿐이고, 나머지 오퍼레이션은 전부
개별 콘텐츠 또는 코드 단위입니다.

**디자인 함의**
- "안동은 정신문화의 수도로…" 같은 **서사형 문단을 큰 자리로 잡으면 채울 수 없습니다.**
- 현재는 가진 데이터로 문장을 구성합니다:
  > 경상북도 안동시에는 관광지 69곳, 음식점 20곳, 착한가격업소 44곳이 등록되어 있습니다.
  > 유교랜드, 안동민속촌, 안동댐 같은 곳을 둘러볼 수 있어요.
- 서사가 꼭 필요하면 **사람이 직접 쓰거나(운영 비용), AI 생성(사실 왜곡 위험)** 중 선택해야 합니다.

## 3. 관광지 상세 설명은 **나중에 도착합니다**

관광지 소개글(`overview`)은 콘텐츠 1건당 API 호출 2회가 듭니다.
6,769건을 전부 채우면 13,000회가 넘고 **1일 한도가 1,000회**라 2주가 걸립니다.

그래서 **사용자가 펼쳐 본 관광지만** 가져와 DB에 저장했습니다(2026-08-11 이전 방식).
한 번 가져오면 영구 보존되어 두 번째부터는 즉시 표시됩니다.

**2026-08-11 부터 선적재 배치를 함께 돌립니다.**
사용자가 펼쳐 보기를 기다리면 커버리지가 늘지 않아, 매일 04:00(KST)에 남는 예산만큼 채웁니다.

| | |
|---|---|
| 실행 | 매일 04:00 KST (`tour.api.backfill.*`) |
| 하루 처리량 | (950 − 사용자 몫 100) ÷ 2회 ≈ **425건** |
| 예상 완료 | 약 15일 |
| 수동 실행 | `POST /admin/sync/tour/details` (`?limit=N` 으로 소규모 확인) |
| 진행률 | `GET /admin/sync/tour/details/progress` |

**디자인 함의**
- 카드/목록에 **설명이 처음부터 채워진 상태를 전제로 하면 안 됩니다.** (배치가 끝날 때까지)
- "자세히" 같은 **명시적 펼치기 동작**이 필요하고, 그 사이 **로딩 상태**가 있어야 합니다.
- 한도 소진 시에는 설명 없이 이름·주소·사진만 나옵니다. 이 상태도 디자인이 필요합니다.

> ⚠ **원본에 설명이 없는 관광지도 있습니다.** 조회를 마쳐도 설명이 안 채워질 수 있어
> `detailFetched` 와 "설명 확보" 수는 다릅니다. 진행률 API 가 둘을 따로 보여줍니다.

## 4. 착한가격업소에는 식당이 아닌 곳이 섞여 있습니다

미용실·세탁소·목욕탕·자동차정비 등이 포함되어 있습니다.
현재는 키워드로 걸러 **먹거리 자리에는 식당만** 노출합니다.

**디자인 함의**
- "이 지역 착한가격업소 N곳" 같은 **총계 숫자와 실제 노출 개수가 다릅니다.**
- 안동 예: 총 44곳이지만 식당만 추리면 그보다 적습니다.

## 5. 사용자 생성 데이터는 **아직 비어 있습니다**

| 데이터 | 현재 |
|---|---:|
| 가입 사용자 | **5** (데모 계정 위주) |
| 저장된 코스 | **1** |
| 후기 | **1건** |

**디자인 함의 — 가장 중요합니다**
- `/reviews`(후기 둘러보기)는 **빈 상태가 사실상 기본 화면**입니다.
  후기 카드가 가득 찬 그리드만 디자인하면 실제로는 그 화면을 볼 일이 없습니다.
- `/my/courses`도 신규 사용자에겐 항상 빈 상태로 시작합니다.
- **빈 상태를 "예외"가 아니라 "첫인상"으로 다뤄주세요.**

## 6. 좌표

| 항목 | 좌표 |
|---|---|
| 관광지 · 음식점 | **있음** |
| **착한가격업소** | **없음 (0 / 12,106)** ⚠ |
| 특산물 | 없음 (장소가 아님) |
| 여행코스 경유지 | 관광지와 매칭될 때만 (46 / 163) |

> ⚠ **2026-08-11 정정**: 이전 문서는 착한가격업소에 좌표가 "있음"으로 적혀 있었으나 **사실이 아닙니다.**
> 행정안전부 원본 CSV 에 위경도 컬럼이 없고, 코드 어디에도 좌표를 채우는 곳이 없습니다
> (`GoodPriceSyncService` 에 `setLat` 호출 없음). **12,106건 전부 `lat/lng = null` 입니다.**

**디자인 함의**
- 코스에 특산물이나 **착한가격업소**를 담으면 목록에는 남지만 **지도에는 찍히지 않습니다.**
- 저장 시 도로 경로 계산에서도 제외됩니다(좌표가 있는 경유지 2곳 이상이어야 계산).
- 그래도 **주소는 있으므로** 코스에서 빼지 않습니다 — 가격 근거가 우리의 유일한 차별점이라
  빼면 그게 통째로 사라집니다. 대신 화면에 "좌표가 없어 지도·이동 추정에서 빠짐"을 밝힙니다.
- 지오코딩(카카오 로컬 API 등)을 붙이면 해소되지만, 12,106건 × 1회 호출이라 별도 배치가 필요합니다.

## 7. 외부 API 한도

| API | 한도 | 쓰는 곳 |
|---|---|---|
| TourAPI | **1,000회/일** (950으로 가드) | 관광지 적재, 상세 조회 |
| 카카오맵 JS | 넉넉 | 지도 표시 |
| 카카오모빌리티 길찾기 | 300회/일(가드) | 코스 경로·거리·시간 |
| Gemini | 무료 등급 분당 제한 | AI 상담 |

**디자인 함의**
- 화면을 열 때마다 외부 호출이 필요한 디자인은 한도를 태웁니다.
- 코스 경로는 **저장 시점에 1회만** 계산하고 저장합니다 →
  **편집 중에는 소요시간·거리를 표시할 수 없습니다**(직선 동선만).

## 8. 늘릴 수 있는 것 / 없는 것

| | 방법 | 비용 |
|---|---|---|
| ✅ 관광지 상세 설명 | 조회 시 자동 축적 or 선적재 배치 | API 호출 |
| ✅ 여행코스 경유지 | 이미 전량 시도함 — API에 없는 게 대부분 | 복구 불가 |
| ✅ 특산물 | 직접 시드 데이터 작성 | 사람 손 |
| ❌ 지역 소개글 | API에 없음 | 직접 작성 또는 AI |
| ❌ 관광지 평점·리뷰수 | TourAPI 미제공 | — |
| ❌ 혼잡도·인기도 | 미보유 | 한국관광 데이터랩 별도 연동 필요 |

> **"인기 순 정렬", "평점 4.5 이상" 같은 UI는 현재 데이터로 만들 수 없습니다.**
> 서비스가 의도적으로 랭킹을 두지 않는 이유이기도 합니다(PRD §2.2 · 제품 원칙 2).
>
> 같은 이유로 **"저평가 지수"나 "비유명 지역" 판정도 만들 수 없습니다.**
> 방문자 수·검색량이 없기 때문입니다. MVP 는 대신 **미방문성 + 콘텐츠 준비도 + 서비스 내부
> 노출 균형(Exposure Balance)** 을 씁니다 — PRD §8.5 · 부록 A 참고.

## 9. TourAPI 공식 코스는 **쓸 수 있는 게 27개뿐입니다**

가장 오해하기 쉬운 부분입니다. "여행코스 347개"라는 숫자만 보면 충분해 보이지만,
**경유지(어디를 어떤 순서로 도는지)가 있는 코스는 27개뿐**입니다.

| | 수 | |
|---|---:|---|
| 여행코스 | 347 | |
| └ 경유지 보유 | **27** | 7.8% |
| └ 경유지 없음 | 320 | **제목 평균 20.5자가 전부** |
| 경유지 행 | 163 | 코스당 평균 6.0곳 |
| └ 관광지와 매칭됨 | 46 | 28% — 나머지는 사진·상세를 따로 받아야 함 |
| **코스가 있는 시군구** | 84 | 34% |
| **경유지 있는 코스가 있는 시군구** | **14** | **5.6%** |
| 코스가 아예 없는 시군구 | **166** | 66% |

**디자인·설계 함의 — 매우 중요합니다**
- 공식 코스를 추천의 기본 단위로 삼으면 **250곳 중 14곳에서만 동작합니다.**
  나머지 236곳은 발견해도 실행 경로가 없어, "코스 데이터가 있는 지역"이라는 **새로운 쏠림**이 생깁니다.
- 그래서 코스는 **공식 코스(27) + 자동 조립 코스(250곳 전역)** 를 한 풀로 다룹니다.
  자동 조립은 `DayPlanService` 가 담당하며, 화면에서 **"공식 코스" / "자동 조립" 배지로 출처를 구분**합니다.
- 공식 코스 27개는 버리는 게 아니라 **자동 조립 규칙을 검증할 정답지**로 씁니다.
- `totalDistance` 가 전량 비어 있어 **"총 거리 0km"가 그대로 노출되지 않도록** 처리가 필요합니다.

> 자세한 설계는 PRD **§8.6 Course Matcher**, 화면 처리는 [SCREENS.md](SCREENS.md) **1.4 코스 선택**을 보세요.
