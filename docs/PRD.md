## A. 이 앱은..

**"국내 여행의 쏠림을 해소하는 발견 플랫폼"** → 거창.. 하지만 담고 싶은 가치

→ 여행자·지역 소상공인·지자체 셋 다 "덜 알려진 곳이 안 알려진다"는 같은 문제를 겪는다..
→ 3자 가치를 다 담을 수 있으면 좋지만 없다면..? 최대한 겹치는 부분을 찾자

**겹치는 지점 = 시군구 코드(SIG_CD) 한 개**
→ 여행자는 그 코드로 지역을 열고, 소상공인은 그 코드 아래 노출되고, 지자체가 푼 공공데이터도 그 코드로 묶인다
→ 하나의 키가 셋을 동시에 만족시킨다. 여기서 출발하자

## B. 만들면서 회고하면서..

**공공데이터는 이미 충분히 있다**
→ 250개 시군구 **전부**에 관광지가 있다(6,769곳). 음식점 8,540곳, 착한가격업소 12,106곳
→ 정보가 없어서 안 가는 게 아니다.. **닿는 채널이 없어서** 안 간다
→ 문제는 데이터가 아니라 **발견 경험**이라는 게 실측으로 확인됨

**"검색"은 쏠림을 재생산한다**
→ 포털·SNS·여행앱은 전부 검색량/리뷰수/예약수로 정렬 → 노출된 곳에 데이터가 더 쌓임
→ 우리가 랭킹 UI를 넣는 순간 똑같은 서비스가 된다..
→ 그래서 지도를 기본 UI로 두고 **모든 지역이 같은 크기의 진입점**을 갖게 함

**애초에 랭킹을 만들 데이터가 없다 (역설적으로 다행)**
→ TourAPI에 평점·리뷰수·혼잡도가 **없음**. "인기순", "평점 4.5↑" 같은 UI는 만들 수가 없다
→ 처음엔 제약이라고 생각했는데.. 방향과 오히려 맞아떨어짐

**지역 소개글이 API에 없다는 걸 뒤늦게 확인**
→ `areaCode2` 응답이 `rnum, code, name` 뿐.. 서사형 문단을 큰 자리로 잡으면 채울 수가 없음
→ 초기엔 "안동은 정신문화의 수도로.." 같은 목업을 넣어놨었는데 전부 걷어냄
→ **가진 숫자로 문장을 조립**하는 쪽으로 선회 (관광지 69곳·음식점 20곳·착한가격업소 44곳..)

**상세 설명은 API 한도에 막힌다**
→ 관광지 1건당 호출 2회, 6,769건 채우면 13,000회.. **1일 한도 1,000회**라 2주 소요
→ 전량 선적재를 포기하고 **사용자가 펼쳐 본 것만** 가져와 영구 저장하는 방식으로 변경
→ 이 결정이 화면 설계를 바꿈: 설명이 처음부터 있다고 전제할 수 없다 → "자세히" 펼치기 + 로딩 상태 필수

**특산물은 10%밖에 없다**
→ 250곳 중 24곳. 처음엔 특산물을 지역 정체성의 축으로 잡았는데 대부분 지역에서 섹션이 통째로 사라짐
→ 없으면 사라지는 걸 **예외가 아니라 기본**으로 두고 설계

**초기 온보딩(취향 2문항)은 아무것도 하지 않았다**
→ "잘 안 알려진 곳 / 잔잔한 곳" 2문항을 받아놓고 **수집만 하고 어디에도 안 씀**..
→ 재미도 없고 쓰이지도 않으니 진입 마찰만 늘리는 화면이었음
→ **여행 MBTI 12문항으로 교체**하고, 결과가 실제로 쓰이는 자리를 세 군데 만듦 (프로필·후기·AI 상담)

**사용자 데이터가 비어 있다는 게 가장 큰 현실**
→ 후기 1건, 코스 소량.. 후기 피드는 **빈 상태가 사실상 기본 화면**이다
→ 카드가 가득 찬 그리드만 디자인하면 실제로는 그 화면을 볼 일이 없음
→ 빈 상태를 첫인상으로 다뤄야 함

**아직 없는 것: 실제 사용자 리서치**
→ 위 근거는 전부 **데이터 실측과 구현 과정에서 나온 것**이지 설문·인터뷰가 아니다
→ "반복 여행에 지쳤다"는 페르소나 전제는 아직 **검증되지 않은 가설**이다 (→ 08 참고)

# [PRD] 시군구 코드 기반의 국내 여행 발견 플랫폼: 숨은여행 (Sumeun)

## 01. Problem (문제 정의)

**여행자**: **목적지가 정해져야 검색이 시작되는데, 그 첫 단계에 도구가 없다.** "국내여행 추천"을 검색하면 광고성 리스트가 나오고 결국 늘 가던 곳(제주·부산·강릉·경주)을 고른다. 낯선 지역을 후보에 올려도 관광지는 A 사이트, 맛집은 블로그, 물가는 알 수 없어 탭 10개를 열다 포기한다. 특히 **가격을 예측할 수 없어** 바가지 우려가 회피 요인이 된다.
→ **첫 화면에서 이탈한다..**

**지역 소상공인**: 착한가격업소로 등록해 가격을 공개해도 **닿을 채널이 없다.** 검색 상위는 이미 유명한 곳이 차지한다.
→ 여행자와 겹치는 부분 많음 — 한쪽은 믿을 가격 정보를 못 찾고, 한쪽은 가진 정보를 못 보여준다

**지자체·공공기관**: TourAPI·착한가격업소로 데이터를 개방했지만 **소비 지점이 없다.** 데이터는 있는데 여행 수요로 전환되지 않는다.

---

## 02. Target User (핵심 사용자 정의)

**주요 사용자 (여행자)**: 갈 만한 데는 대충 다 가봤다는 감각이 있고, SNS에 안 나온 곳을 선호하지만 직접 발굴할 리서치 체력은 없는 **20~30대 1~2인·커플 여행자**. 주말/연휴 2~3주 전, **목적지 미정 상태**에서 막연히 탐색을 시작한다.

**보조 사용자 (후기 작성자)**: 다녀온 코스를 기록으로 남기고 싶은 사용자. 공공데이터가 채우지 못하는 **"가볼 만한가"라는 주관적 판단**을 공급한다. 여행자와 같은 사람이지만 **여행 후(後) 시점**의 다른 역할이다.

**이해관계자 (지역 소상공인·지자체)**: 착한가격업소 표에 업소명·메뉴·가격이 그대로 노출되는 것이 직접적인 가치. *다만 현재 서비스와 계약·정산 관계는 없다 — 데이터를 인용할 뿐이다.*

---

## 03. Solution Concept (솔루션 컨셉)

> **"랭킹 없는 지도에서 목적지 없이 시작해, 시군구 코드 하나로 조립된 지역 정보를 보고, 나만의 코스로 완성하는 서비스"**

**설계 원칙 3가지**

1. **목적지가 없는 상태에서 시작한다.** 기존 서비스는 "안동 검색"부터 시작하지만, 우리는 **"어디로 갈까?"** 상태를 첫 진입점으로 삼는다 → 지도 클릭 · 랜덤 룰렛 · AI 상담
2. **검색이 아니라 지도로 탐색한다.** 리스트/랭킹은 쏠림을 재생산한다. 전국 250개 시군구 폴리곤을 기본 UI로 두어 **모든 지역이 동등한 진입점**을 갖는다
3. **한 지역의 정보는 한 화면에 모은다.** 관광지·먹거리·착한가격업소·특산물·추천 코스를 **SIG_CD 하나로 조인**해 단일 번들로 제공한다

---

## 04. Core Features & Value (핵심 기능 및 사용자의 불안 해소)

### 1순위: 랭킹 없는 탐색 엔진 (발견 중심)

**기능 1. 전국 시군구 탐색 지도** — 검색창 대신 250개 폴리곤. 클릭하면 우측 패널에 요약(특산물·착한가격업소·추천 반일 코스)이 슬라이드로 뜬다. **정렬도 순위도 없다.**
→ 검색어를 몰라도 탐색이 시작된다. 쏠림을 UI 차원에서 구조적으로 차단

**기능 2. 랜덤 여행지 룰렛** — 여러 지역이 순차로 점멸하다 한 곳에서 멈춘다(3~4초).
→ "아무 데나 좋으니 새로운 곳" 니즈에 즉답. 선택 피로 자체를 없앤다

**기능 3. 통합 지역 상세** — 지표 4종(관광지/맛집/착한가격업소/특산물 수) · 지역 소개 · 추천 코스 카드 · 착한가격업소 표 · 카카오맵 길찾기.
→ 파편화된 정보를 한 화면으로 통합. **숫자 지표로 "여기 볼 게 있나"를 즉시 판단**하게 함

**기능 4. 착한가격업소 가격 공개** — 업소명·메뉴·가격·주소를 행정안전부 데이터 그대로 노출.
→ **낯선 지역의 최대 회피 요인인 가격 불확실성을 공식 데이터로 해소.** 유명 지역이 못 가진 우리만의 근거

### 2순위: 성향 기반 매칭 (개인화 중심)

**기능 5. 여행 MBTI 진단(12문항)** — 계획성(J/P) 4문항 · 정보 해석(S/N) 2문항 · 판단 기준(T/F) 3문항 · 에너지(E/I) 3문항 → 16유형.
→ 초기 설정 단계에서 취향을 **재미있게** 수집. 결과가 실제로 세 군데에서 쓰인다

**기능 6. AI 여행 상담** — 자연어로 물으면 지역·코스를 추천하고 **이동 버튼**을 함께 준다. 로그인 상태면 MBTI 성향을 프롬프트에 반영한다.
→ *"마음에 담는 몽상가인 INFP 성향에 어울리는 고요한 영월군을 추천해 드려요"*
→ **모델이 지어내지 못하게** DB 실재 목록만 프롬프트에 넣고, 응답 ID를 다시 DB로 검증한 뒤에만 버튼을 만든다

**기능 7. 오늘의 숨은 여행지** — 지역 미선택 시 좌측에 카드 무한 스크롤.
→ 아무것도 안 눌러도 발견이 계속 일어난다

### 3순위: 실행과 순환 (리텐션 중심)

**기능 8. 내 코스 만들기** — 좌측 후보(관광지/먹거리/착한식당/특산물)에서 담아 우측 타임라인 구성, 드래그로 순서 변경.
→ 발견에서 끝나지 않고 **실행 가능한 결과물**로 연결

**기능 9. 실제 도로 경로 표시** — 저장 시 카카오모빌리티로 경로를 1회 계산해 저장. 지도에 선·화살표가 순서대로 그려진다.
→ 메모장+지도앱 수작업을 대체. *한도 때문에 편집 중에는 계산하지 않는다*

**기능 10. 후기 작성·공유·피드** — 사진 5장 + 줄글 + 공개 여부. 상세는 공유 링크의 대상이고, 피드에서 남의 후기를 본다. **작성자 MBTI 뱃지가 붙는다.**
→ **탐색 루프를 닫는 기능.** ① 다녀온 뒤 돌아올 이유가 생기고 ② 남의 후기가 곧 덜 알려진 지역의 콘텐츠가 된다
→ 후기 상세에는 항상 "이 지역 보기 / 코스 만들기" 복귀 경로를 둔다. **후기는 읽고 끝나는 글이 아니라 다음 여행의 진입점이다**

### 가치 요약

| 사용자 문제 | 대응 기능 | 전달 가치 |
|---|---|---|
| 어디로 갈지 모름 | 기능 1·2·6·7 | 목적지 없이 시작 가능한 탐색 |
| 정보 파편화 | 기능 3 | 지역당 단일 통합 화면 |
| 가격 불확실 | 기능 4 | 공식 데이터 기반 가격 신뢰 |
| 동선 수작업 | 기능 8·9 | 담기 → 경로 → 완성 |
| 재방문 이유 없음 | 기능 5·10 | 남의 후기가 새 지역의 발견 입력이 됨 |

## 05. User Flow (사용자 흐름)

**여행자(신규·목적지 미정)**: 앱 실행 ➔ 회원가입 ➔ **여행 MBTI 12문항** ➔ 지도에서 지역 클릭 / 룰렛 / AI 상담 ➔ 우측 패널 요약 확인 ➔ 지역 상세에서 지표·착한가격업소 가격 확인 ➔ 후보 담아 코스 구성 ➔ 저장 ➔ **경로·거리·시간 확인**

**여행 후(後)**: 내 코스 ➔ 후기 작성(사진+줄글+공개 여부) ➔ 후기 상세 ➔ **링크 복사해 공유**

**발견 루프(다른 사람 → 나)**: 후기 피드 ➔ 후기 상세(작성자 MBTI 뱃지) ➔ **"이 지역 보기"** ➔ 지역 상세 ➔ 코스 만들기 ➔ 다시 저장 ➔ 다시 후기

> 이 루프가 기능 10의 존재 이유다. 공공데이터는 **"무엇이 있는지"**를 알려주지만
> **"가볼 만한지"**는 다녀온 사람만 알려줄 수 있다.

**예외 흐름** — 데이터 미적재 지역 → 빈 상태 UI · 위치 권한 거부 → 목적지만으로 길찾기 · 남의 코스/비공개 후기 접근 → 리다이렉트 · API 한도 소진 → 설명 없이 이름·주소·사진만

## 06. Success Metrics (가장 중요한 한 가지 성공 지표)

### **"낯선 지역 코스 완성률"**

사용자가 **한 번도 고려해본 적 없던 시군구**를 앱 안에서 발견해 코스로 저장했는지 측정.

**정의**: 신규 가입자 중 7일 이내에 [목적지 미정 진입 ➔ **비(非)유명 시군구** 상세 진입 ➔ 코스 저장]까지 이탈 없이 마친 비율 **20% 달성**
*비유명 = 검색량 상위 20개 시군구(제주·부산·강릉·경주 등)를 제외한 나머지 230곳*

**이유**: 이 서비스의 존재 이유는 "쏠림 해소" 하나다. 사용자가 유명 지역을 고르면 우리가 아니어도 됐던 여정이고, 발견만 하고 저장하지 않으면 실행으로 이어지지 않은 구경이다. **처음 보는 지역을 실제 계획으로 바꿨을 때만** 문제 정의가 증명된다.

**보조 지표** — 탐색된 고유 시군구 수/세션 · 착한가격업소 항목 클릭률(가격 근거의 실효성) · 코스 저장 → 후기 작성 전환율 · **후기 열람 → 그 지역 상세 진입률**(발견 루프 가설)

## 07. 추가 화면 및 기능

**여행 MBTI 결과를 세 군데에 심기** — 검사만 하고 끝나면 초기 온보딩과 같은 실수다
→ 프로필 뱃지 · 후기 피드/상세 뱃지 · AI 상담 프롬프트
→ 특히 피드: **"어떤 성향의 사람이 어떤 코스를 다녀와 어떻게 느꼈는지"**가 한눈에 읽히게

**발자국 로고 + 디자인 토큰 체계**
→ 강아지·고양이 발자국 한 짝씩. 색·타이포·간격을 CSS 변수로 뽑아 리디자인 시 **이름은 유지하고 값만 교체** 가능하게

**Figma 반입용 자체 완결형 HTML 22종**
→ Tailwind Play CDN을 쓰기 때문에 원본 `.html`을 복사하면 스타일이 없는 뼈대만 넘어감
→ CSS를 미리 빌드해 인라인한 파일로 뽑아 `html.to.design`에 그대로 붙여넣을 수 있게

**아직 안 한 것**
→ 소셜 로그인(카카오·구글 — 버튼 자리만 있고 동작 안 함)
→ 관광지 상세 설명 커버리지 확대(현재 0.5%, API 한도 문제)
→ 운영 DB 전환(현재 H2 파일 DB), `/h2-console`·`/admin` 차단

## 08. 확인이 더 필요한 가정

지금 근거는 **데이터 실측**이지 사용자 리서치가 아니다. 아래는 아직 검증되지 않았다.

| 가정 | 왜 위험한가 | 확인 방법 |
|---|---|---|
| "반복 여행에 지쳐 새로운 곳을 원한다" | **전체 전제.** 틀리면 서비스 자체가 성립하지 않음 | 설문 — 최근 국내 여행지 선택 이유 |
| 랭킹이 없는 게 불편하지 않다 | 평점 없는 목록이 오히려 판단 불가로 느껴질 수 있음 | 지도 UI 사용성 테스트 |
| 착한가격업소가 실제 선택 근거가 된다 | 우리의 유일한 차별점인데 아무도 안 볼 수도 있음 | 클릭률 측정 |
| 후기가 쌓인다 | **현재 1건.** 안 쌓이면 발견 루프 전체가 작동하지 않음 | 초기 사용자 대상 후기 작성률 |
| 여행 MBTI가 재미로 소비된다 | 12문항은 짧지 않다. 중간 이탈률 확인 필요 | 문항별 이탈 지점 측정 |
