## 문서 요약

### 제품 한 줄 정의

> 검색할 목적지가 없어도 랭킹 없는 지도에서 지역을 발견하고, 짧은 조건으로 후보를 비교한 뒤
> 실제로 갈 수 있는 코스로 완성한다. 반복 사용에서는 좋았던 여행의 공통 경험을 학습해 발견을 개인화한다.

| 항목 | 결정 |
|---|---|
| 핵심 문제 | 공공 관광데이터는 충분하지만, 검색·인기순 중심 채널 때문에 낯선 지역이 여행 후보에 오르기 어렵다. |
| 핵심 사용자 | 새로운 국내 여행지를 원하지만 직접 발굴·조사할 시간은 부족한 20~30대 1~2인 여행자. |
| 차별점 | 랭킹 없는 발견 + 근거가 보이는 지역 비교 + 모든 시군구를 커버하는 공식/자동 조립 코스. |
| AI 역할 | 추천 이유를 자연어로 설명하고, 검증된 장소·코스 ID를 연결한다. 사실·공간·가격은 DB와 계산 로직이 보증한다. |
| North Star | **낯선 지역 실행 전환율** — 신규 사용자가 미방문 지역을 발견하고 코스를 저장·공유한 비율. |
| 대회 MVP | 목적지 없는 발견, 빠른 조건 입력, 지역 비교, 공식/자동 조립 코스, 저장·공유, 기본 추천 근거, 이벤트 로깅. 개인화는 구조화 기반으로 검증한다. |
| 비범위 | 영상 숏폼, 자체 예약, 실시간 행동 재학습, Contextual Bandit, 완전한 운영시간 검증. |

### 이번 개정의 핵심

- 과거 논의 과정(구형 챗봇 중심 설계, "파인튜닝 불필요" 문구, 공식 코스 단독안)을 본문에서 제거하고 **현재 결정만** 남겼다.
- "모든 지역이 같은 크기"를 **"모든 지역에 동일한 탐색·클릭 권한"** 으로 수정했다. 실제 폴리곤 면적은 다르다.
- 검색량 데이터가 없으므로 **"비유명/저평가"를 임의 판정하지 않는다.** MVP에서는 미방문성·콘텐츠 준비도·서비스 내 노출 균형을 사용한다.
- TourAPI 공식 코스의 실측 커버리지 부족을 반영해 **공식 코스와 자동 조립 코스를 동일 스키마**에서 다룬다.
- 여행 MBTI는 **선택형 재미 요소**로 내리고, 추천의 핵심 입력은 방문 지역·만족도·경험 태그로 교체했다.
- 제품 경험을 **발견 → 판단 → 실행**의 세 단계로 재정의했다. 데이터가 많다는 사실보다 사용자가 하나의 여행지를 선택하고 코스를 완성하는지가 우선이다.
- 긴 온보딩 대신 **빠른 조건 칩과 점진적 질문**을 기본 입력으로 둔다. 방문 이력과 Traveler DNA는 반복 사용을 위한 선택형 개인화 경로다.
- 착한가격업소는 핵심 차별점으로 주장하지 않는다. 데이터 품질과 사용자 반응이 확인된 경우에만 가격 근거·필터로 노출한다.

## 1. 제품 배경과 문제 정의

### 1.1 문제 관찰

개발 DB 실측 결과, 250개 시군구 **모두**에 관광지가 존재한다. 관광지 6,769곳, 음식점 8,540곳,
착한가격업소 12,106곳이 이미 수집되어 있다. 따라서 핵심 문제는 "데이터 부재"보다
**"여행자가 낯선 지역을 발견하고 선택할 수 있는 소비 경험의 부재"** 에 가깝다.

기존 포털·SNS·여행 서비스는 목적지 검색과 인기·리뷰·예약 신호를 중심으로 탐색을 시작한다.
이 구조는 이미 알려진 장소를 빠르게 찾는 데는 유리하지만, 사용자가 이름조차 모르는 지역을
후보에 올리는 데는 약하다. 다만 이 인과관계와 사용자 수요는 **아직 실제 사용자 조사로 검증되지 않았으며**,
본 PRD에서는 핵심 가설로 취급한다.

### 1.2 이해관계자별 문제

| 대상 | 현재 문제 | 숨은여행이 제공할 가치 |
|---|---|---|
| 여행자 | 목적지가 정해져야 검색을 시작할 수 있고, 낯선 지역은 정보·가격·동선 불확실성 때문에 포기한다. | 목적지 없는 지도 탐색, 빠른 조건 입력, 비교 가능한 근거 카드, 코스 저장·길찾기. |
| 지역 소상공인 | 가격·메뉴를 공개해도 기존 검색 상위 노출을 얻기 어렵다. | 시군구 상세와 자동 조립 코스 안에서 착한가격업소를 사실 기반으로 노출한다. |
| 지자체·공공기관 | 개방 데이터가 실제 여행 탐색과 행동으로 이어지는 소비 지점이 부족하다. | SIG_CD 기반으로 데이터를 통합하고 지역 발견·코스 실행 이벤트로 연결한다. |

### 1.3 공통 데이터 축

관광지·음식점·착한가격업소·지역 경계·코스를 **시군구 코드(SIG_CD)** 로 통합한다.
SIG_CD는 이해관계자의 가치를 자동으로 보장하는 사업모델이 아니라,
서로 다른 데이터를 같은 지역 경험으로 조립하게 하는 **핵심 데이터 키**다.

> **핵심 가설**
> 목적지가 정해지지 않은 여행자에게 "랭킹 없는 발견 → 과거 여행 기반 개인화 → 검증 가능한 지역 정보
> → 코스 저장·길찾기"를 하나의 흐름으로 제공하면, 사용자는 기존에 방문하지 않은 지역도
> 실제 여행 후보로 채택한다.

## 2. 목표와 비목표

### 2.1 제품 목표

1. 목적지 없이도 지역 탐색을 시작할 수 있게 한다.
2. 빠른 조건 입력만으로 사용자가 실제로 선택할 수 있는 후보를 만든다.
3. 후보를 비교할 때 추천 이유·데이터 출처·누락 정보를 명확히 보여준다.
4. 발견한 지역을 시간·거리·장소 구성에 맞는 코스로 연결하고 저장·공유하게 한다.
5. 반복 사용자를 위해 방문 이력과 행동 기반 개인화를 점진적으로 추가한다.
6. 지역 노출과 사용자 행동을 측정해 추천 모델의 후속 학습 기반을 만든다.

### 2.2 비목표

- 모든 여행 예약·결제를 자체 구축하지 않는다.
- 인기순·평점순·숨은 점수 순위를 사용자에게 제공하지 않는다.
- LLM이 존재하지 않는 장소, 가격, 운영시간, 이동거리를 생성하게 하지 않는다.
- 대회 MVP에서 숏폼 영상 플랫폼이나 대규모 소셜 피드를 구축하지 않는다.
- 검색량·방문자 데이터가 없는 상태에서 "전국 비유명 지역"을 객관적으로 판정했다고 주장하지 않는다.

## 3. 핵심 사용자와 사용 맥락

### 3.1 Primary Persona

20~30대 1~2인·커플 국내 여행자. 국내 여행 경험이 누적되어 새로운 곳을 원하지만,
낯선 지역을 직접 발굴하고 관광지·음식·가격·동선을 여러 서비스에서 조사할 시간은 부족하다.
주말이나 연휴 1~3주 전, **목적지를 정하지 않은 상태**에서 탐색을 시작한다.

### 3.2 핵심 Job-to-be-Done

> **JTBD**
> "이번 여행에서 어디로 갈지 모르겠을 때, 내가 예전에 좋아했던 경험과 연결되면서도
> 처음 가보는 지역을 부담 없이 발견하고, 실제로 사용할 코스까지 빠르게 만들고 싶다."

### 3.3 핵심 사용 상황

사용자는 긴 설문을 작성하러 오지 않는다. 다음과 같이 짧은 선택만으로 탐색을 시작한다.

```text
이번 주말 어디 갈까?
  [서울 출발] [부산 출발] [현재 위치]
  [반일] [당일치기] [1박 2일]
  [조용한 곳] [바다] [산책] [맛집] [역사]
  [차 있음] [대중교통]
```

선택하지 않은 값은 합리적인 기본값으로 처리하고, 결과를 보여준 뒤 필요한 질문만 추가한다.
방문 이력 입력은 개인화 품질을 높이는 선택형 경로이며, 첫 가치 경험을 막아서는 안 된다.

### 3.4 검증이 필요한 사용자 가설

| 가설 | 위험 | 검증 |
|---|---|---|
| 반복 여행자는 새로운 국내 지역을 원한다. | 전체 수요 가설이 틀리면 제품의 필요성이 약해진다. | 15~20명 문제 인터뷰 및 최근 여행지 선택 과정 조사. |
| 방문 지역 3~7개를 입력할 의향이 있다. | 온보딩 이탈이 높으면 개인화 엔진이 시작되지 않는다. | 단계별 완료율, 3개 입력 시점 이탈률. |
| 랭킹 없는 지도가 판단 불가로 느껴지지 않는다. | 사용자가 익숙한 지역만 누를 수 있다. | 지도/리스트 프로토타입 비교, 첫 선택 시간과 신규 지역 선택률. |
| 착한가격업소가 낯선 지역 선택의 근거가 된다. | 관심이 낮으면 핵심 데이터 가치가 약하다. | 가격 항목 노출 대비 열람·코스 담기율. |
| 자동 조립 코스가 실행 의도를 만든다. | 코스 품질이 낮으면 발견이 저장으로 이어지지 않는다. | 공식/자동 조립 코스 블라인드 선호 비교. |
| 짧은 조건 입력만으로도 후보를 고를 수 있다. | 조건을 많이 물으면 검색보다 번거로워진다. | 3~5개 칩 입력 후 첫 후보 선택 시간과 포기율 측정. |
| 비교·실행 정보가 범용 AI보다 유용하다. | 단순 추천은 GPT·Claude로 대체될 수 있다. | 동일 조건을 범용 AI와 비교해 실제 선택률·사실 일치율 측정. |

## 4. 제품 원칙

1. **발견은 열어두고, 실행은 검증한다.** 조건 검색으로 후보를 먼저 닫지 않되, 선택 후에는 데이터 신뢰도와 코스 준비도를 보여준다.
2. **랭킹은 없애되 판단 근거는 없애지 않는다.** 지역별 경험 태그, 데이터 수, 추천 이유, 출처를 제공한다.
3. **모든 시군구에 동일한 탐색 권한을 준다.** 지도 면적은 다르지만 모든 폴리곤은 클릭 가능하고 상세 진입 경로를 갖는다.
4. **AI는 의미를 이해하고, DB는 사실을 보증한다.** 생성 문장은 검증된 지역·장소·코스 ID에만 연결한다.
5. **없는 데이터가 기본이다.** 특산물·설명·공식 코스가 없을 때 섹션이 자연스럽게 축소되거나 자동 조립 경로로 대체되어야 한다.
6. **학습 자체가 아니라 개선을 증명한다.** 파인튜닝 모델은 인간 평가셋에서 베이스라인을 넘을 때만 채택한다.
7. **입력은 짧게, 정보는 점진적으로.** 첫 화면에서 긴 폼·회원가입·MBTI를 요구하지 않고, 사용자가 선택한 만큼만 질문한다.
8. **결과는 영감이 아니라 다음 행동으로 끝난다.** 후보 비교에서 코스 저장·공유·길찾기까지 한 흐름으로 연결한다.

## 5. 핵심 사용자 경험

### 5.1 신규 사용자 흐름 — 발견에서 실행까지

```
앱 진입 → 빠른 조건 칩 3~5개 선택(또는 바로 지도)
       → 발견 묶음·후보 카드 3개 확인
       → 후보 비교(거리·시간·데이터 근거·부족한 정보)
       → 지역 상세 → 공식 또는 자동 조립 코스 확인·편집
       → 저장 → 길찾기 / 공유
       → (선택) 방문 이력 입력 → Traveler DNA 개인화 강화
```

### 5.2 후보 비교와 코스 실행

후보 카드는 순위를 매기지 않고, 사용자가 선택할 수 있도록 동일한 형식의 근거를 제공한다.

| 표시 항목 | 원칙 |
|---|---|
| 추천 이유 | 닮은 경험·새로운 경험·선택 가능한 근거를 한 문장으로 표시 |
| 거리·시간 | 출발지와 이동수단을 기준으로 계산하거나 추정임을 표시 |
| 데이터 상태 | 출처·갱신 시점·설명/좌표/운영시간 누락을 표시 |
| 코스 결과 | 반일·당일·1박 2일 중 선택하고 장소 수·이동 순서를 제시 |
| 다음 행동 | `[코스 만들기]` `[저장]` `[공유]` `[길찾기]`를 명확히 제공 |

코스가 완전한 실행을 보장하지 못하면 “갈 수 있는 코스”가 아니라 **“구성 가능한 코스”**로 표현한다.

### 5.3 재방문 흐름

```
지도 재진입 → 이전 방문·저장·탐색 기록 확인 → 아직 방문하지 않은 발견 묶음 탐색
           → 지역 또는 코스 저장 → 행동 신호가 Traveler DNA 갱신 후보로 기록
```

### 5.4 여행 후 흐름

```
저장 코스 → 방문 완료 또는 만족도 입력 → (선택) 사진·후기 작성
         → 후기 상세의 "이 지역 보기 / 이 코스 담기" → 다른 사용자의 발견 루프로 연결
```

### 5.5 예외 흐름

- **설명 미적재** — 이름·주소·이미지와 구조화 지표만 제공하고 "자세히" 요청 시 수집·로딩 상태를 표시한다.
- **공식 코스 없음** — 자동 조립 코스를 제공하고 출처를 명확히 구분한다.
- **운영시간 미보유** — "운영시간 미검증" 경고를 표시하며 실행 가능성을 단정하지 않는다.
- **위치 권한 거부** — 현재 위치 기반 거리 대신 목적지 중심 정보와 외부 길찾기 연결을 제공한다.
- **AI 실패/한도 소진** — 구조화 특징 기반 추천과 템플릿 설명으로 폴백한다.

### 6.2 P1 — MVP 안정화

- **랜덤 룰렛** — 완전 무작위가 아니라 최소 데이터 품질과 코스 생성 가능성을 통과한 지역에서 선택한다.
- **오늘의 숨은 여행지** — 빈 공간 채우기가 아니라 개인화 발견 묶음의 재노출 수단으로 사용한다.
- **선택형 여행 MBTI** — 프로필·후기 뱃지·설명 톤에 활용하되 추천 핵심 로직과 분리한다.
- **후기 작성·공유** — 사진과 짧은 글 중심. 영상 업로드는 제외한다.
- **동행자 공유·투표** — 저장한 코스를 링크로 공유하고 후보를 비교하는 기능.
- Cross-Encoder 리랭커, 행동 기반 Traveler DNA 갱신, 방문 후 만족도 반영.

### 6.3 P2 — 사용자 데이터 확보 후

- Contextual Bandit을 이용한 탐색/활용 비율 조정.
- 동행자 취향 결합, 계절·날씨 문맥, 실제 방문 기반 코스 신뢰도.
- 자동 여행 리캡 및 구조화 후기 피드.
- 외부 방문자·검색량 데이터 연동 후 객관적 Under-Exposure 정의 검토.

### 7.1 데이터 품질 원칙

- 모든 레코드에 `source`, `sourceUpdatedAt`, `ingestedAt`을 저장한다.

## 8. AI·데이터 분석 설계

### 8.1 전체 구조

> **핵심 구조**
> 공공데이터 → Region DNA → 방문 이력 기반 Traveler DNA → 순위 없는 개인화 발견 묶음
> → 공식/자동 조립 Course Matcher → 저장·공유·길찾기 → 행동 로그 → 후속 재학습

### 8.2 역할 분리

| 구성 | 담당 역할 | 학습 여부 |
|---|---|---|
| 구조화 분석 | 콘텐츠 비율, 다양성, 공간 밀집도, 코스 준비도, 데이터 신뢰도 | 규칙·통계 계산 |
| 관광 도메인 임베딩 | 취향 표현과 지역·코스 경험의 의미적 유사도 | **사전학습 모델 파인튜닝** |
| 발견 점수 | 유사도·새로움·코스 준비도·노출 균형·불확실성 결합 | 초기 수식, 후속 학습 가능 |
| LLM | 추천 근거를 자연어로 번역 | 별도 파인튜닝 없음 |
| DB·서비스 | 지역·장소·코스 ID, 가격, 출처 검증 | 학습 없음 |
| 코스 조립 | 공식 코스 우선, 없으면 DayPlanService 자동 조립 | 규칙 기반 MVP |

### 8.3 Region DNA

Region DNA는 정답 레이블이 없는 지역 특성을 억지로 예측하는 모델이 아니다.
**구조화 특징과 의미 임베딩을 결합한 표현**이다.

```
RegionDNA(r) = [ StructuredFeatures(r) ‖ SemanticEmbedding(r) ]
```

- **구조화 특징** — 관광 콘텐츠 구성비, 다양성 엔트로피, 관광지 좌표 기반 밀집도·분산도,
  음식점·가격 데이터 존재, 공식/자동 코스 준비도, 데이터 완전성·최신성.
- **의미 특징** — 관광지 상세와 지역 내 장소 설명을 관광 도메인 임베딩 모델로 인코딩하고 신뢰도 가중 집계.
- **외부 표현** — 자연·골목·시장·역사·휴식 등 경험 태그와 짧은 설명.
  내부 원시 점수나 순위는 노출하지 않는다.

### 8.4 Traveler DNA

방문 사실을 선호로 곧바로 간주하지 않는다. **만족도와 입력 구체성에 따라 가중치와 신뢰도를 다르게** 적용한다.

| 입력 수준 | 사용 표현 | 신뢰도 |
|---|---|---|
| 지역 + 만족도 + 기억나는 장소 | 장소 및 연결 코스 임베딩 | 높음 |
| 지역 + 만족도 + 경험 태그 | Region DNA의 해당 차원 강조 | 중간 |
| 지역 + 만족도 | Region DNA 전체를 축소 가중 | 낮음 |

초기 Traveler DNA는 두 표현을 혼합한다.

```
A. 방문 지역 임베딩 가중 평균
   다시 가고 싶음 +1.0 · 좋았음 +0.7 · 보통 0 · 나와 맞지 않음 −0.7
B. 구조화 입력으로 만든 자연어 취향 프로필의 임베딩

TravelerDNA = α·A + (1−α)·B      초기 α = 0.6~0.8, 사용자 검증으로 선택
```

### 8.5 발견 점수와 랭킹 없는 노출

```
DiscoveryScore(u,r) = α·TasteSimilarity + β·Serendipity + γ·CourseReadiness
                    + δ·ExposureBalance − λ·Redundancy − μ·Uncertainty
```

- **TasteSimilarity** — Traveler DNA와 Region DNA의 의미·구조 유사도.
- **Serendipity** — 기존 취향과 연결되면서 새로운 경험 차원을 제공하는 정도.
- **CourseReadiness** — 공식 또는 자동 조립 코스를 제공할 수 있는 정도.
- **ExposureBalance** — 서비스 내부 노출 횟수가 적은 후보에 기회를 부여. **검색량 기반 "저평가"와 구분한다.**
- **Redundancy** — 방문 지역·최근 추천·같은 유형의 반복 페널티.
- **Uncertainty** — 설명·좌표·코스·데이터 최신성 부족 페널티.

점수는 **후보 생성과 묶음 구성에만** 사용하고 UI에서 1위~10위로 표시하지 않는다.
노출 묶음은 다음 네 가지로 구성한다.

| 묶음 |
|---|
| 익숙한 결, 새로운 지역 |
| 한 걸음 넓히는 지역 |
| 아직 경험 못 한 결 |
| 데이터가 찾은 새로운 가능성 |

### 8.6 Course Matcher

공식 코스만으로는 **14개 시군구만 커버**되므로, 공식 코스와 자동 조립 코스를 같은 Course DNA 스키마로
표현한다. 공식 코스가 유효하면 우선 제시하고, 없거나 경유지가 불충분하면 DayPlanService 결과를 제공한다.

- **공식 코스** — "공식 코스" 출처 배지, 원본 코스·장소 ID 유지.
- **자동 조립** — "자동 조립" 배지, 사용 규칙과 데이터 미검증 항목 표시.
- **공통 Course DNA** — 지역, 장소 유형 구성, 의미 임베딩, 예상 일정 유형, 공간 밀집도,
  착한가격업소 포함 여부, 데이터 신뢰도.
- 운영시간 커버리지가 낮으므로 MVP에서는 "실행 가능 보장"이 아니라 **"코스 구성 가능"** 으로 표현한다.

### 8.7 추천 설명과 환각 방지

| 설명 칸 | 예시 | 검증 근거 |
|---|---|---|
| 닮은 점 | 군산에서 좋았던 골목·시장 경험과 유사합니다. | 사용자 긍정 지역, 공통 태그·임베딩 근거 |
| 새로운 점 | 기존 여행에 적었던 강변 산책이 더해집니다. | 후보 지역의 차별 태그 |
| 갈 수 있는 근거 | 자동 조립 반나절 코스로 관광지 3곳과 지정 가격 업소 1곳을 연결했습니다. | 실제 지역·장소·코스 ID |

- LLM에 전체 데이터를 넣지 않고 **추천 후보와 검증된 근거만** 주입한다.
- 응답에 등장하는 지역·장소·코스 ID를 **DB에서 재검증한 뒤** 버튼을 만든다.
- 가격·운영시간·거리·존재 여부는 **생성 모델 출력값을 사실로 사용하지 않는다.**
- LLM 실패 시 템플릿 기반 3단 설명으로 폴백한다.

## 9. 모델 학습 계획

### 9.1 학습 목표

> **단일 학습 목표**
> 여행 취향 표현과 지역·관광지·코스 설명을 하나의 관광 경험 임베딩 공간에 배치한다.
> 범용 모델이 표면 단어는 비슷하지만 실제 경험이 다른 여행을 구분하도록 만든다.

모델은 **Bi-Encoder / Sentence-Transformer 계열, 공유 인코더 Siamese 구조**로 시작한다.
100M~500M 규모의 한국어 또는 다국어 사전학습 임베딩 모델을 후보로 비교한다.
손실함수는 **InfoNCE 또는 Multiple Negatives Ranking Loss**를 사용하고,
In-batch Negative와 Hard Negative를 함께 사용한다.

### 9.2 학습 데이터

| 단계 | 데이터 | 용도 |
|---|---|---|
| 자기지도 | 관광지 제목↔상세, 코스 설명↔하위 장소, 같은 코스의 장소 | 기본 관광 관계 학습. 공식 코스 경유지 데이터가 적어 보조적. |
| 합성 데이터 | 검증된 설명을 바탕으로 생성한 취향 질의, 부분 일치, Hard Negative | 약 250개 지역·6,769개 관광지에서 Cold Start 학습쌍 생성. |
| 인간 평가셋 | 실제 사람이 쓴 취향 문장 200~500개, 후보 적합도 0~3점 | **학습에 사용하지 않는 최종 평가 전용.** |
| 행동 데이터 | 노출 후 저장·공유·길찾기·방문·거절 | 서비스 공개 후 Phase 2 재학습. |

### 9.3 합성 데이터 품질 규칙

- 질의에 **지역명이나 정답 장소명이 직접 포함된 샘플 제거.**
- 원문 복사, 중복, 지나치게 일반적인 문장, 원천 데이터에 없는 경험 추가 제거.
- "바다"처럼 표면 단어는 겹치지만 드라이브·어촌 휴식·해양 레저처럼 경험이 다른 **Hard Negative**를 포함한다.
- 합성 문장 생성 모델의 편향을 별도로 기록하고 Human Test와 성능 격차를 보고한다.

### 9.4 데이터 분할과 평가

문장 단위 무작위 분할은 같은 지역에서 생성한 유사 문장이 학습·평가에 동시에 들어가
성능을 부풀리므로 **금지한다.**

- **Train** — 특정 지역·관광지·코스 집합.
- **Validation** — 학습과 겹치지 않는 후보 집합.
- **Region Holdout Test** — 지역 전체를 학습에서 제외해 미지 지역 일반화 평가.
- **Human Test** — 사람의 실제 취향 문장과 0~3 관련성 레이블.

### 9.5 비교군과 교체 조건

| 모델 | 설명 |
|---|---|
| A. BM25 | 키워드 검색 베이스라인 |
| B. 사전학습 임베딩 | 파인튜닝하지 않은 한국어/다국어 모델 |
| C. 구조화 특징 | Region DNA 구조화 차원의 유사도 |
| D. 관광 도메인 파인튜닝 | 합성·자기지도 데이터로 학습한 Bi-Encoder |
| E. 결합 모델 | D의 의미 유사도 + C의 구조화 특징 및 신뢰도 |

평가 지표: Recall@5/10, MRR, nDCG@10, Region Holdout, Human Relevance 평균, 추천 다양성, Serendipity.

> **교체 조건** — D 또는 E가 **Human Test의 nDCG@10과 평균 적합도 모두에서 B를 넘을 때만**
> 서비스 모델로 채택한다. 개선이 없으면 **B+C를 유지한다.**

### 9.6 Phase 2 행동 학습

| 신호 | 예시 |
|---|---|
| Positive | 지역 저장, 코스 저장, 공유, 길찾기 실행, 방문 완료, 긍정 후기 |
| Hard Negative | 노출 후 반복 넘김, 코스 열람 직후 이탈, 저장 취소, 방문 후 부정 평가, 코스에서 장소 삭제 |
| **사용 금지 Negative** | **사용자에게 노출되지 않은 지역·코스** |

행동 기반 학습은 **impression 로그를 전제**로 한다.
실제 행동 데이터가 충분히 쌓이기 전에는 학습 효과를 주장하지 않는다.

#### impression 정의 — "화면에 그려짐"이 아니라 "사용자가 봄"

Negative 는 *"보여줬는데 안 골랐다"* 여야 한다. *"아예 못 봤다"* 를 Negative 로 쓰면
모델은 사용자가 존재조차 모르는 지역을 "싫어하는 지역"으로 학습한다.

지도는 250개 폴리곤을 한 번에 렌더하므로 **"렌더됨 = 노출됨"이 성립하지 않는다.**
세션마다 250건을 기록하면 그중 대부분이 가짜 Negative 가 된다.

| 등급 | 판정 기준 | weight | 학습 사용 |
|---|---|---:|---|
| **강한 노출** | 후보 카드가 뷰포트에 **50% 이상 · 1초 이상** 보임 | 1.0 | Hard Negative 로 사용 |
| **약한 노출** | 발견 묶음에 선택되어 지도 폴리곤이 강조됨 | 0.3 | 보조 신호. Hard Negative 로 쓰지 않음 |
| **기록 안 함** | 폴리곤이 그려지기만 함 · 스크롤로 스쳐 지나감 | — | — |

- 판정은 `IntersectionObserver { threshold: 0.5 }` + 1초 체류 타이머로 한다.
  `map.js` 의 '오늘의 숨은 여행지' 무한 스크롤이 이미 같은 패턴을 쓴다.
- 한 세션에서 같은 지역이 반복 노출되면 **1회로 합치고 노출 횟수만 센다**(반복 넘김 신호로 별도 활용).
- `discovery_event.impressionId` 로 노출과 이후 행동(상세 진입·저장·길찾기)을 연결한다.
  같은 impression 에 후속 행동이 없으면 그것이 Hard Negative 후보다.

> ⚠ **impression 은 소급 복구가 불가능하다.** 저장·클릭은 DB 에 남지만
> "보여줬는데 안 고른 것"은 그 순간 기록하지 않으면 영원히 사라진다.
> Phase 2 는 나중이지만 **로깅은 서비스 오픈 전에 심어야 한다** — F-09 가 P0 인 이유다.

## 10. 데이터 파이프라인과 시스템 구조

### 10.1 오프라인 배치

1. TourAPI·착한가격업소·지역 경계 데이터를 SIG_CD 기준으로 정규화한다.
2. 관광지 상세 설명을 **일 950회 가드**로 선적재하고 수집 상태를 기록한다.
3. 구조화 Region DNA와 Course DNA를 계산한다.
4. 사전학습 모델로 지역·관광지·코스를 임베딩해 베이스라인 벡터를 저장한다.
5. 합성 질의와 Hard Negative를 생성·필터링한다.
6. 세라프 GPU 서버에서 임베딩 모델을 파인튜닝한다.
7. 새 모델로 전체 벡터를 재계산하고 **모델 버전 단위로 원자적 교체**한다.

### 10.2 온라인 요청

```
방문 이력 입력 → Traveler DNA 계산 → 미방문 지역 필터
             → 전체 250개 지역에 대해 발견 점수 계산 → 묶음별 후보 구성
             → 선택 지역의 공식/자동 조립 코스 매칭
             → 검증된 근거를 LLM 또는 템플릿으로 설명 → DB ID 재검증 → 화면 표시
```

### 10.3 검색·저장 방식

지역 250개, 관광지 6,769개 규모에서는 **벡터 DB가 필수적이지 않다.**
1,024차원 float32 관광지 벡터는 약 26MB이며 메모리 전수 비교가 가능하다.
초기에는 애플리케이션 메모리 또는 관계형 DB에 저장하고,
규모·지연이 실제 병목으로 확인되면 pgvector/FAISS를 검토한다.

### 10.4 주요 스키마

| 테이블 | 핵심 필드 |
|---|---|
| `visited_region` | userId, sigCd, sentiment, tags[], placeIds[], confidence, createdAt |
| `traveler_dna` | userId, vector, alpha, source, modelVersion, updatedAt |
| `region_dna` | sigCd, structuredFeatures, embedding, modelVersion, exposureBalance, dataConfidence |
| `course_dna` | courseId, origin(official\|assembled), vector, durationClass, placeIds[], dataConfidence |
| `discovery_event` | userId, sigCd, courseId, action, impressionId, weight, createdAt<br/>action: `impression_strong` \| `impression_weak` \| `detail` \| `save` \| `remove` \| `share` \| `route` \| `skip`<br/>impressionId 로 노출과 후속 행동을 연결한다 (§9.6) |
| `embedding_job` | entityType, entityId, modelVersion, sourceHash, status, updatedAt |

## 11. 성공 지표와 분석 설계

### 11.1 North Star

> **낯선 지역 실행 전환율**
> 신규 사용자 중 7일 안에 목적지 없이 탐색을 시작해 미방문 지역을 확인하고,
> 해당 지역의 코스를 저장하거나 공유한 사용자 비율.
>
> **분모** 빠른 조건 입력을 완료하거나 지도에서 후보 카드를 1회 이상 본 신규 사용자.
> **분자** 미방문 지역 상세 진입 후 공식 또는 자동 조립 코스를 저장·공유한 사용자.

초기 목표 20%는 **가설값**이며 파일럿의 실제 분포로 재보정한다. 개인화 온보딩 완료를 North Star의 전제조건으로 두지 않는다.
검색량 데이터가 없는 동안 "비유명 상위 20개 제외" 같은 임의 정의는 North Star에서 사용하지 않는다.

### 11.2 퍼널 지표

| 단계 | 지표 |
|---|---|
| 진입 | 빠른 조건 입력 시작률, 3~5개 칩 완료율, 첫 후보 선택까지 걸린 시간 |
| 온보딩 | 방문 지역 3개 도달률, 완료율, 태그·장소 선택률, 여행 DNA 동의율 |
| 발견 | 묶음 노출→지역 상세 진입률, 세션당 고유 시군구 수, 미방문 지역 선택률 |
| 판단 | 후보 비교 완료율, 추천 근거 열람률, 데이터 경고 이탈률, 조건 변경률 |
| 계획 | 지역 상세→코스 확인률, 코스 저장률, 코스 수정률, 자동/공식 코스 선호 |
| 실행 | 저장→공유율, 저장→길찾기 클릭률, 코스 복제·동행자 투표율, 여행 당일 재열람률 |
| 학습 | impression 대비 positive/negative 신호율, 모델 버전별 전환 비교 |

### 11.3 대회용 실험

- **추천 실험** — 인기/무작위가 아닌 베이스라인 B와 개인화 E를 비교해 적합성·새로움·저장 의도를 측정한다.
- **코스 실험** — 공식 코스와 자동 조립 코스를 출처를 가린 상태에서 비교해 이해도·매력도·수정 필요성을 측정한다.
- **지도 실험** — 랭킹 없는 지도에서 첫 선택 시간, 탐색 지역 수, 선택 확신을 측정한다.
- **모델 실험** — A~E의 오프라인 성능과 정성 사례를 함께 제시한다. **실측하지 않은 수치는 발표에 사용하지 않는다.**

|---|---|---|
| W1 | 데이터 정규화, 빠른 조건 칩, 후보 카드, 이벤트 설계 | 발견→판단 퍼널 동작, 스키마 확정 |
| W2 | 지역 비교, 반일/당일/1박 2일 자동 조립, 저장·공유·길찾기 연결 | **실행 가능한 코스 데모** |
| W3 | 공식/자동 코스 품질 점검, 데이터 상태·출처 표시, 기본 추천 baseline | 250개 지역 후보 품질 점검 |
| W4 | 선택형 방문 이력 온보딩, Traveler DNA v0, 발견 묶음 | 구조화 기반 개인화 데모 동작 |
| W5 | 실제 사용자 10~20명 프로토타입 테스트, 범용 AI 비교 | 첫 후보 선택률·실행 전환 기준 고정 |
| W4 | 도착 설명으로 베이스라인 임베딩, 합성 질의 생성 | A~C 베이스라인, 학습 데이터 초안 |
| W5 | Human Test 200~500건, 사용자 프로토타입 테스트 | 평가셋 고정, UX 문제 목록 |
| W6 | 세라프에서 T1 대조학습 | 모델·학습 로그·재현 설정 |
| W7 | 전량 재임베딩, Region Holdout/Human Test, 교체 판정 | D/E 비교 결과, 서비스 모델 결정 |
| W8 | 통합 안정화, 대회 데모·발표 자료 | 학습→분석→발견→코스→행동 데모 |

### 14.1 Go/No-Go 게이트

- **G1 데이터** — 상세 설명 수집률과 품질이 학습 문서 생성 기준을 충족하는가?
- **G2 UX** — 30초 내 조건 입력 완료율, 첫 후보 선택률, 코스 저장·공유율이 수용 가능한가?
- **G3 모델** — D/E가 Human Test에서 B를 모두 상회하는가? 아니면 B+C로 폴백한다.
- **G4 코스** — 자동 조립 코스가 블라인드 평가에서 최소 품질 기준을 통과하는가?
- **G5 데모** — 모든 추천 문장이 실제 지역·장소·코스 ID로 재검증되는가?

## 15. 대회 심사 기준 대응

| 심사 기준 | 숨은여행의 주장 | 증거 |
|---|---|---|
| 창의성·차별성 | 인기순을 제거한 지도 위에서 "과거 여행과 닮았지만 미방문인 지역"을 순위가 아닌 발견 묶음으로 제시. | 지도 UX, Traveler DNA, 발견 묶음 비교. |
| 대중성·실용화 | 목적지 미정 탐색부터 조건 입력·지역 비교·코스 저장·길찾기까지 한 흐름. | 30초 입력 완료율, 낯선 지역 실행 전환율, 사용자 선택 테스트. |
| 기술적 난이도 | SIG_CD 다중 데이터 통합, Region/Traveler/Course DNA, 관광 도메인 대조학습, Region Holdout, DB 검증. | A~E 모델 비교, 파이프라인 로그, 데모. |
| 디자인 | 랭킹 없이도 판단 가능한 테마 색·근거 카드·발견 묶음, 모바일 바텀시트. | 프로토타입과 접근성 점검. |

> **발표 핵심 문장**
> 숨은여행은 공공데이터를 예쁘게 보여주는 지도가 아닙니다.
> 사용자가 좋았던 여행에서 취향을 역산하고, 범용 모델이 구분하지 못하는 관광 경험의 차이를 학습해,
> 아직 가보지 않은 지역을 발견시키고 실제 코스로 연결합니다.

### 15.1 권장 데모 시나리오

1. 사용자가 출발지·기간·분위기·이동수단을 3~5개 칩으로 선택하거나 바로 지도로 진입한다.
2. 숨은여행이 순위를 매기지 않은 지역 후보 3개를 추천 이유와 함께 보여준다.
3. 사용자는 후보를 비교하며 거리·예상 시간·데이터 상태·코스 준비도를 확인한다.
4. 지역을 선택하면 과거 여행과 닮은 점, 새로운 점, 실제 코스 근거를 보여준다.
5. 공식 코스가 있으면 공식 코스를, 없으면 자동 조립 코스를 제시하고 출처를 표시한다.
6. 사용자가 반일·당일·1박 2일 중 하나를 선택해 코스를 저장하고 길찾기·공유로 이어간다.
7. 반복 사용을 원하면 방문 이력을 입력하고 Traveler DNA 기반 발견 묶음을 확인한다.

## 부록 A. 용어 정의

| 용어 | 정의 |
|---|---|
| 미방문 지역 | 온보딩 및 이후 기록에서 사용자가 방문했다고 표시하지 않은 시군구. **"비유명"과 동일하지 않다.** |
| 발견 묶음 | 내부 점수를 순위로 노출하지 않고 서로 다른 추천 이유로 구성한 지역 후보 그룹. |
| Region DNA | 지역의 구조화 관광 특징과 의미 임베딩을 결합한 표현. |
| Traveler DNA | 방문 지역·만족도·태그·장소와 이후 행동으로 추론한 연속형 취향 표현. |
| Course DNA | 공식 또는 자동 조립 코스의 장소 구성·의미·공간·신뢰도 표현. |
| Exposure Balance | 서비스 내부 노출 횟수의 편중을 완화하는 요소. **외부 검색량 기반 인기도가 아니다.** |
| Course Readiness | 해당 지역에서 공식 또는 자동 조립 코스를 제공할 수 있는 정도. |
| Human Test | 학습에 사용하지 않고 실제 사람이 작성·평가한 최종 모델 평가셋. |
