# 숨은여행 — 제품 요구사항 정의서 (PRD v4.0)

> **목적지는 우연으로, 여행은 우리 취향으로.**
>
> 유명한 여행지만 반복해서 가는 데 지친 여행객이 전국 250개 구역 지도에서
> 랜덤으로 새로운 목적지를 발견하고, 자신과 친구의 취향을 반영한 여러 날의 여행 계획을 함께 만드는 국내 여행 서비스.

- 작성일: 2026-09-08
- 문서 성격: 이번 회의 결정을 반영한 **목표 제품 PRD**. 현재 구현 완료를 뜻하지 않는다.
- 제품명: 저장소에서 사용하는 ‘숨은여행’을 작업명으로 유지한다.
- 구현 기준: 작성일 작업 트리의 주요 코드와 기존 PRD 확인. 운영 DB 수량·배포 상태는 재실측하지 않았다.
- 기준 문서: 이 문서가 향후 기획·개발 범위의 기준이다. 기존 `prd.txt`는 과거 제안이며 현재 요구사항이 아니다.
- 이전 수정본: [v3 보존본](archive/PRD-v3-before-2026-09-08.md)
- 관련 문서: [화면 정의](SCREENS.md), [데이터 현황](DATA.md), [디자인 토큰](DESIGN-TOKENS.md). 관련 문서는 기존 구현 설명으로, v4 목표와 다를 수 있다.

## 1. 결정 요약과 적용 범위

### 1.1 회의에서 확정한 방향

| 항목 | 제품 결정 |
|---|---|
| 핵심 페르소나 | 유명한 곳만 가서 지겨워하는 여행객 |
| 온보딩 | 사용자의 여행 성향을 먼저 받는다 |
| 메인 화면 | 프로젝트의 전국 250개 구역 지도 |
| 목적지 발견 | 랜덤 버튼으로 한 지역에 도착한다 |
| 랜덤 경험 | 다트 또는 친구 아바타를 싣는 대포처럼 놀이성을 가진 연출 |
| 개인화 시점 | 도착 지역에서 ‘이 지역으로 여행 떠나기’를 누른 뒤 코스를 구성한다 |
| 동행 개인화 | 함께 가는 친구가 있으면 친구의 여행 취향도 반영한다 |
| 관광지 | 한국관광공사 데이터의 실제 관광지·이미지·상세 설명을 사용한다 |
| 이동 | 카카오맵과 카카오모빌리티를 활용해 동선·거리·소요 시간을 보여준다 |
| 여러 날 계획 | 여행 일수를 선택하고 Day 1, Day 2 등 날짜별로 편집한다 |
| 숙소 | 코스 위치를 기준으로 에어비앤비 등 외부 숙소 검색에 연결한다 |
| 함께 계획 | 상세 계획 화면에서 친구를 초대하고 함께 일정을 만든다 |
| 간접 가치 | 관광의 지역 분산, 과밀 관광 완화, 소외 지역 소상공인 성장 기회 |

‘상세 계획 창에서 친구를 짤 수 있도록’은 **친구를 초대하고 함께 계획을 짠다**는 뜻으로 해석한다. 낯선 동행자 매칭은 포함하지 않는다.

### 1.2 실행을 위해 정한 기본안

아래는 회의의 확정 사항과 구별되는 **PRD 제안 기본값**이다. 구현을 시작할 수 있도록 정했으며 사용자 테스트와 팀 검토로 조정할 수 있다.

| 항목 | 제안 기본값 |
|---|---|
| 대표 연출 | 대포 + 동행 아바타를 우선 시안으로 삼되, 다트와의 최종 선택은 시안 비교 후 확정 |
| 음식점 | MVP 자동 추천에서 보류. 식사 시간·메모는 지원 |
| 기간 | 1~7일, 기본 1일. 날짜 없이 일수만으로도 계획 가능 |
| 인원 | 본인 포함 1~8명. 미응답 친구 때문에 계획 생성을 막지 않음 |
| 이동 | MVP 자동 경로·시간은 자동차 기준. 다른 수단은 외부 길찾기와 별도 안내 |
| 추첨 | 조건을 만족하는 지역 단위 균등 추첨, 같은 탐색 세션에서는 소진 전 중복 방지 |
| 회원 | 비회원도 온보딩·추첨·개인 초안 편집 가능. 서버 저장·초대·공동 편집은 로그인 |
| 공동 편집 | 초대 수락한 회원이 편집. 저장 버전 검사로 충돌 방지, 실시간 커서는 후속 |
| 숙소 | 외부 검색 연결 + 사용자가 선택한 숙소를 일정에 직접 등록 |
| 개인화 방식 | 설명 가능한 규칙 기반으로 시작. 모델 학습은 MVP 필수 요건이 아님 |

### 1.3 이전 기획과 달라진 점

- 다이어리 작성 필수 진입을 성향 온보딩으로 바꾼다. 기존 여행 기록은 선택 기능으로 남긴다.
- 취향으로 지역 후보 3개를 고르는 흐름을 랜덤 지역 1개 도착으로 바꾼다.
- 취향은 **선택된 지역 안에서 코스를 구성하는 데** 사용한다.
- 공식 코스가 있는 지역만 추천하던 조건을 없앤다. 관광지 기반 조립 코스가 기본이다.
- 하루 개인 코스를 여러 날의 공동 여행 계획으로 확장한다.
- 음식점·착한가격업소·특산물은 기존 데이터가 있어도 신규 핵심 코스의 필수 요소로 두지 않는다.
- 다이어리·후기·상담·근처 추천은 보조 기능으로 유지하고 신규 메인 흐름의 필수 단계에서 제외한다.

## 2. 문제, 사용자, 가치

### 2.1 사용자 문제

여행을 가고 싶어서 검색하지만 반복해서 보이는 유명 지역과 익숙한 코스를 다시 선택한다.
새로운 곳에 가보고 싶어도 어디를 골라야 할지 모르고, 낯선 지역을 고른 뒤에는 관광지·동선·숙소를 다시 조사해야 한다.
친구와 함께라면 서로 다른 취향을 조율하는 부담도 생긴다.

**핵심 문제는 새로운 목적지를 선택하는 어려움과, 그 선택을 실행 가능한 일정으로 만드는 수고다.**

### 2.2 핵심 페르소나

| 구분 | 정의 |
|---|---|
| 대상 | 유명한 곳만 반복해서 가는 데 지친 국내 여행객 |
| 상황 | 여행 의향과 동행자는 있지만 목적지는 열려 있는 상태 |
| 바람 | 평소라면 고르지 않았을 지역에서 자신이 좋아하는 방식으로 여행하기 |
| 불편 | 비슷한 검색 결과, 낯선 곳에 대한 정보 부족, 동행 취향 조율, 동선 조사 |
| 행동 동기 | 랜덤 도착의 재미, 새로운 장소에 대한 호기심, 계획 수고 감소 |
| 거부 요인 | 너무 먼 목적지, 취향과 무관한 코스, 과도한 일정, 친구 취향 무시 |
| 성공한 경험 | “생각도 못 한 곳인데, 이렇게 다니면 우리도 재밌겠다”라고 느끼고 계획을 저장 |

나이·직업·성별은 핵심 조건으로 고정하지 않는다. 예시 인물은 국내 여행 경험이 있고 친구들과 주말 여행을 준비하는 직장인으로 설정할 수 있지만, 확정된 시장 조사 결과로 표현하지 않는다.

**사용자 요구:** “매번 비슷한 유명 여행지로 가기 싫을 때, 새로운 목적지를 재미있게 정하고 우리 취향에 맞는 일정까지 한 번에 만들고 싶다.”

### 2.3 이해관계자와 효과의 경로

| 이해관계자 | 기대 가치 | 확인해야 할 근거 |
|---|---|---|
| 여행자 | 새로운 목적지 발견, 일정 준비 부담 감소 | 새로움 평가, 계획 완료율, 소요 시간 |
| 동행 친구 | 취향이 반영되고 계획에 참여할 기회 | 초대 수락, 취향 입력, 공동 편집, 만족도 |
| 관광 집중 지역 주민·운영자 | 방문 집중 완화 가능성 | 외부 방문·혼잡 데이터와 비교 |
| 상대적으로 덜 방문되는 지역 | 관광객 접점과 방문 기회 증가 | 지역별 선택·실제 방문 분포 |
| 지역 소상공인 | 방문객의 숙박·식사·체험 소비 기회 | 동의 기반 소비 조사·제휴 실적 등 후속 자료 |
| 관광 정보 제공기관 | 보유 정보의 활용 확대 | 출처 준수, 정보 조회·연결 실적 |

효과 가설은 **지역 노출 분산 → 목적지 선택 분산 → 실제 방문 분산 → 현지 소비 → 반복 방문과 사업 성장 가능성**이다.
랜덤 추첨만으로 오버투어리즘 해결이나 소상공인의 지속 성장을 보장하지 않는다.
특히 음식점 추천을 제외한 MVP에서 지역 소비는 간접 기대 효과다.

### 2.4 제품 목표와 비목표

목표는 재미있는 목적지 결정, 개인·그룹 취향을 반영한 코스, 여러 날의 편집 가능한 일정, 숙소 탐색과 공유까지의 연결이다.

MVP에 포함하지 않는 것은 숙박 예약·결제, 예약 가능 여부·가격 보장, 자체 내비게이션, 검증되지 않은 맛집 랭킹, 낯선 동행자 매칭, 비용 정산, 항공·철도 예약, 자동 다지역 순회, 학습 모델 구축이다.

## 3. 제품 원칙

1. **지역은 랜덤, 코스는 취향 맞춤.** 목적지를 취향으로 은밀하게 결정하지 않는다.
2. **여행의 주도권은 사용자에게 있다.** 다시 뽑기, 직접 선택, 코스 수정이 가능하다.
3. **재미 이후에 실행 정보가 따른다.** 도착 화면은 관광지와 계획 시작으로 바로 이어진다.
4. **동행자의 응답과 선택을 존중한다.** 참여하지 않은 친구의 취향을 추정하거나 공개하지 않는다.
5. **전국 지도와 추첨 가능 범위를 구분한다.** 모든 구역이 보여도 일시적으로 추첨에서 제외될 수 있다.
6. **실재하는 장소만 추천한다.** 설명·운영시간·이동시간의 누락을 사실처럼 채우지 않는다.
7. **수정한 일정은 보존한다.** 친구 추가와 재추천이 기존 계획을 자동 덮어쓰지 않는다.
8. **여행 가능성을 과장하지 않는다.** 이동 예상, 운영 확인, 숙소 예약 상태를 구분한다.

## 4. 전체 사용자 여정과 화면

### 4.1 기본 흐름

```text
첫 방문 → 여행 성향 온보딩 → 전국 지도
                              ↓
                 혼자 / 친구 참여 선택
                              ↓
               랜덤 발사 → 지역 도착 카드
                    ↑          ↓
                 다시 뽑기   이 지역으로 여행 떠나기
                               ↓
                 일수·이동수단·참여자 확인
                               ↓
                      취향 맞춤 코스 생성
                               ↓
                상세 계획: Day별 관광지·시간·동선
                   ↔ 친구 초대·취향 반영·공동 편집
                   ↔ 숙소 검색·선택 숙소 등록
                               ↓
                      저장·공유·계획 확정
                               ↓
                      여행 당일 다시 열기
```

재방문자는 저장한 성향으로 지도에 바로 진입한다. 친구 없이 시작한 계획에도 상세 계획 화면에서 친구를 추가할 수 있다.

### 4.2 화면 명세

| 화면 | 주요 요소 | 핵심 행동 |
|---|---|---|
| 성향 온보딩 | 경험 태그, 여행 속도, 제외 조건, 진행 상태 | 성향 저장 후 지도 진입 |
| 메인 지도 | 250개 구역, 랜덤 장치, 동행 아바타, 추첨 범위, 내 여행 | 랜덤 발사 또는 직접 지역 선택 |
| 도착 카드 | 지역명, 강조된 영역, 실제 관광지 이미지·설명, 관광지 예시 | 여행 떠나기 / 다시 뽑기 |
| 여행 조건 | 일수·날짜, 인원·응답 현황, 이동수단, 하루 사용 시간 | 맞춤 코스 만들기 |
| 상세 계획 | Day 탭, 장소 목록, 선택 Day 지도, 시간 합계, 숙소, 참여자 | 추가·삭제·순서/Day 이동·재추천·저장 |
| 관광지 상세 | 사진, 설명, 주소, 출처, 운영 정보·확인 상태 | 일정에 담기 / 외부 지도 열기 |
| 초대 참여 | 초대자·목적지·권한, 로그인, 참여 동의, 성향 입력 | 참여 수락 |
| 내 여행 | 초안/확정 여행, 날짜·지역, 참여자 | 이어서 편집 / 다시 열기 |

모바일은 지도와 바텀시트, 상세 계획의 목록/지도 전환을 기본으로 한다.
데스크톱은 일정 목록과 지도를 나란히 배치한다.
지역 배경처럼 보이는 관광지 사진에는 실제 장소명을 표시한다.

## 5. 기능 요구사항

우선순위 **P0**는 MVP 필수, **P1**은 핵심 흐름 완성 후, **P2**는 후속 검증 대상이다.
아래 수용 기준은 목표이며 현재 통과 결과가 아니다.

### F-01. 여행 성향 온보딩 — P0

- 경험 태그 1~5개와 여행 속도를 받는다. 아무 태그도 선택하지 않는 경우 ‘아직 모르겠어요’를 선택할 수 있다.
- 초기 태그는 자연·바다·산·산책·골목·역사·휴식·실내·체험 등 기존 분류를 재사용하되, 음식 관련 선호가 식당 추천을 약속하지 않도록 설명한다.
- 여행 속도는 여유롭게/보통/알차게로 받고, 명시적 제외 조건은 선택 입력으로 제공한다.
- 방문 이력, 과거 여행 글, MBTI는 필수 입력에서 제외한다.
- 출발지·날짜·이번 이동수단은 프로필 성향과 구분해 여행별로 받는다.
- 비회원 입력은 임시 보관하고 로그인할 때 계정 값과 비교해 사용자가 선택한 값을 이관한다.
- 성향은 프로필과 상세 계획에서 다시 수정할 수 있다.
- ‘성향은 도착한 지역의 코스에 반영돼요’라고 미리 설명한다.

**수용 기준:** 최초 온보딩으로 지도까지 진입할 수 있고, 재접속·로그인 이관 시 입력이 불필요하게 사라지지 않는다. 무응답을 특정 취향으로 간주하지 않는다.

### F-02. 전국 지도 메인 — P0

- 프로젝트의 250개 구역과 식별자 체계를 유지한다. 250개를 최신 행정구역 수라고 단정하지 않고 데이터셋 버전을 관리한다.
- 초기 지도에는 인기순·별점순 지역 랭킹을 두지 않는다.
- 모든 구역은 클릭·터치·키보드 또는 지역 검색으로 확인할 수 있다.
- 랜덤 장치를 주 행동으로, 직접 선택을 보조 행동으로 제공한다.
- 지도 렌더가 실패하면 지역 목록과 랜덤 결과 카드로 이어갈 수 있다.
- 도착한 작은 구역은 확대·라벨로 구분하며 이전 지도 위치로 돌아갈 수 있다.

**수용 기준:** 250개 구역의 ID가 지역 데이터와 연결되고, 랜덤 결과의 구역·이름·상세 데이터가 일치한다.

### F-03. 랜덤 추첨과 애니메이션 — P0

**추첨 정책**

- 기본 풀은 지도에 존재하고 사용 가능한 관광지가 있는 지역이다.
- 자동 생성 가능 여부는 좌표와 유효한 장소 정보를 기준으로 판정한다. MVP 제안 기준은 관광지 2곳 이상이며, 이미지·설명 부족만으로 지역 전체를 제외하지 않는다.
- 공식 코스 보유, 사용자 선호 점수, 인기도, 지도 면적은 지역 확률의 가중치로 사용하지 않는다.
- 기본은 전국이다. 사용자가 명시적으로 고른 시도 범위와 방문 지역 제외 조건만 반영한다.
- 방문 지역 제외는 방문 기록이 있는 사용자에게만 제공하고 기본값은 꺼짐이다.
- 남은 후보 지역이 N개면 각 지역의 추첨 확률은 1/N이다. 좌표를 무작위로 찍어 넓은 지역이 유리해지는 방식을 사용하지 않는다.
- 같은 탐색 세션에서는 이미 뽑은 지역을 제외한다. 모두 소진되면 사용자에게 알리고 새 회차를 시작한다. 범위를 바꾸면 회차도 새로 시작한다.
- 후보가 0개면 조건 완화 또는 직접 선택을 제공한다. 몰래 범위를 넓히지 않는다.
- ‘현재 추첨 가능 N개 지역’을 확인할 수 있게 한다. 제외 원인은 데이터·사용자 조건별로 관측한다.

**연출 정책**

- 서버가 지역 ID를 먼저 확정하고 애니메이션은 그 결과를 연출한다.
- 대포안: 참여 아바타 선택 → 대포에 넣기 → 발사 → 지도 이동 → 구역 착지 → 도착 카드.
- 아바타를 여러 명 넣어도 일행 전체가 같은 지역에 도착한다. 선택된 참여자를 발사 전에 확인한다.
- 다트안: 실행 → 다트 비행 → 당첨 구역 표시 → 도착 카드. 두 연출을 MVP에서 모두 만들 필요는 없다.
- 아바타 드래그에는 클릭·탭 ‘함께 넣기’ 대체 조작을 제공한다.
- 반복 클릭은 한 요청으로 처리한다. 네트워크 재시도는 같은 요청 ID에 동일한 결과를 반환한다.
- 애니메이션은 제안 목표 2~4초, 건너뛰기 제공. 모션 감소 설정에서는 짧은 강조로 대체한다.
- 발사음은 기본 꺼짐. 실패 시 무한 발사·로딩 없이 재시도 상태로 돌아온다.
- 애니메이션과 관계없이 마지막 도착 지역을 다시 열 수 있다.

**수용 기준:** 넓은 지역이 더 자주 뽑히지 않고, 중복 클릭·재시도·모션 생략에도 서버 결과와 화면 결과가 일치한다.

### F-04. 지역 도착과 여행 시작 — P0

- 도착 카드에 지역명·시도, 관광지 사진, 확보된 소개, 대표 관광지 예시를 제공한다.
- 이 단계에서 ‘취향에 맞춰 뽑힌 지역’이라고 설명하지 않는다.
- 주 버튼은 ‘이 지역으로 여행 떠나기’, 보조는 ‘다시 뽑기’, ‘지도에서 보기’다.
- 여행 시작 후 목적지를 고정하고 기간·참여자 조건으로 코스 생성을 진행한다.
- 기간을 채울 관광지가 부족하면 만들 수 있는 범위를 안내하고 일수 축소·빈 일정 편집·다른 지역 선택을 제안한다.
- 데이터 부족 때문에 다른 지역으로 자동 변경하지 않는다.
- 직접 선택으로 들어온 계획은 랜덤 유입과 구분해 기록한다.

**수용 기준:** 어떤 도착 결과에서도 계획 시작이나 명확한 복구 행동이 가능하다.

### F-05. 개인·그룹 맞춤 코스 — P0

- 선택 지역의 실제 관광지를 기본 후보로 사용한다.
- 지역이 아니라 **관광지 선택·조합·순서·Day 배정**을 개인화한다.
- 출발 시각·하루 사용 시간·속도·필수 포함/제외 장소를 함께 반영한다.
- 추천 이유는 “산책 선호를 반영한 공원과 둘레길”처럼 실제 장소와 태그에 연결한다.
- 공식 코스는 참고 후보로 활용할 수 있으나 필수 조건으로 삼지 않는다.
- 재조립한 코스는 ‘취향 맞춤 코스’로 표시하고 한국관광공사가 이 개인화 결과를 추천한 것처럼 표현하지 않는다.
- 중복 장소를 여러 Day에 자동 삽입하지 않는다. 숙소 반복과 사용자가 의도적으로 추가한 재방문은 허용한다.
- 운영일 정보가 있으면 적용하고, 없으면 확인 필요 상태를 표시한다.
- 명시적으로 제외한 조건을 풀어야만 생성 가능한 경우 조건 변경을 사용자에게 요청한다.

**수용 기준:** 같은 지역에서도 다른 성향 입력이 장소 선택 또는 추천 근거에 반영되고, 결과 장소 ID가 DB에서 검증된다. 충족하지 못한 조건이 결과에 표시된다.

### F-06. 여행 일수와 상세 계획 — P0

- 1~7일을 선택하고 Day 1부터 해당 일수만큼 탭을 만든다. 날짜 선택은 선택 사항이다.
- 날짜를 지정하면 시작일과 일수로 종료일을 계산하고 Day 탭에 실제 날짜를 함께 표시한다.
- Day별 관광지 추가·삭제·교체·순서 변경·다른 Day로 이동을 지원한다.
- 관광지별 예상 체류 시간을 수정할 수 있다.
- 식당 자동 추천 없이도 ‘점심 60분’ 같은 식사·휴식 블록과 메모를 넣을 수 있다.
- 일정이 빈 Day도 저장할 수 있다. ‘계획 중’ 상태를 보여주며 완성된 하루처럼 표현하지 않는다.
- 일수 증가 시 빈 Day를 추가하며 추가 Day 생성은 별도 실행한다.
- 일수 감소 시 없어질 Day의 항목을 보여주고 이동 또는 삭제를 명시적으로 선택하게 한다.
- ‘이 Day 다시 추천’과 ‘전체 다시 추천’을 구분한다. 고정한 장소는 유지하고 새 결과는 적용 전 비교한다.
- 하루 사용 시간 초과 시 초과분과 줄일 항목을 제시한다.
- 확정 후에도 수정 가능하지만 수정하면 초안으로 돌아가고 변경 상태를 보여준다.
- 계획 확정은 모든 Day에 관광지 1곳 이상이 있고 미저장 변경이 없을 때 가능하다. 운영·숙소 확인 경고는 남겨두되 여행 예약 완료를 뜻하지 않는다.

**수용 기준:** Day 간 이동·일수 감소·재추천·새로고침 이후 장소가 중복되거나 조용히 유실되지 않는다. 저장된 순서·체류 시간·Day가 복원된다.

### F-07. 지도 동선·거리·소요 시간 — P0

- 카카오맵은 장소 마커와 경로를 표시하고, 카카오모빌리티는 자동차 도로 경로·예상 거리·시간을 계산한다.
- 선택 Day의 장소 순서와 지도 번호를 일치시킨다.
- 구간별 이동시간, 하루 이동 합계, 관광 체류 합계, 식사·휴식, 총 계획 시간을 구분한다.
- Day별 시작·종료 위치를 지정할 수 있다. 미지정 시 첫 관광지부터 마지막 관광지까지의 시간임을 표시한다.
- 출발지→첫 관광지와 마지막 관광지→귀가지는 위치가 등록된 경우 포함하고, 미등록 시 전체 여행시간에 포함되지 않았다고 알린다.
- 코스 편집이 끝나면 해당 Day 경로를 갱신한다. 변경 전 경로를 최신 경로처럼 보여주지 않는다.
- 경로 캐시 키는 장소 순서·좌표·이동수단·필요 시 출발시간을 포함하고 계산 시각을 저장한다.
- 교통 상황에 따라 달라지는 예상 시간임을 표시하고 명시적 새로고침을 제공한다.
- 도로 경로 응답이 없으면 ‘이동시간 확인 필요’로 표시한다. 직선거리 추정을 제공한다면 별도 추정 라벨을 붙인다.
- 좌표 누락·한 장소·부분 구간 실패는 해당 구간만 명확히 표시한다. 미계산 구간을 0분으로 합산하지 않는다.
- 도보·대중교통 사용자는 외부 길찾기를 확인할 수 있다. 자동차 시간을 해당 수단의 시간으로 보여주지 않는다.
- 도서 지역의 배편·항공편 등 미지원 연결은 수동 확인 대상으로 남긴다.

카카오 지도 표시 기능과 자동차 길찾기의 역할은 공식 문서를 기준으로 구분했다.
[카카오맵 Web API](https://apis.map.kakao.com/web/documentation/),
[카카오모빌리티 자동차 길찾기](https://developers.kakaomobility.com/guide/navi-api/directions).

**수용 기준:** 장소 순서 변경 시 해당 Day의 경로가 갱신되고, 미계산 구간이 있으면 하루 전체 이동시간을 확정값처럼 표시하지 않는다.

### F-08. 숙소 검색 연결과 일정 반영 — P0

- 2일 이상 계획에서 숙박이 필요한 밤마다 ‘이 일정 주변 숙소 찾기’를 제공한다.
- 기본 검색 기준점은 해당 Day 마지막 관광지다. 사용자는 다음 Day 첫 장소 주변 또는 직접 입력한 지역으로 바꿀 수 있다.
- 단순 좌표 평균이 바다·산간에 떨어지는 문제를 피하도록 실제 장소를 검색 기준점으로 삼는다.
- 지역·주소·날짜·인원을 보여주고 외부 서비스로 이동한다.
- Airbnb 검색 화면의 위치·날짜·인원 조건 전달은 공개 지원 여부와 실제 동작을 검증한 범위에서만 제공한다.
- 자동 조건 전달이 지원되지 않으면 검색어 복사와 Airbnb 열기를 함께 제공한다. 검증하지 않은 URL 매개변수에 의존하지 않는다.
- 사용자가 고른 숙소의 이름·주소·외부 링크·선택 좌표를 직접 등록할 수 있다.
- 좌표가 등록되면 전날 종료와 다음 날 시작 동선에 반영한다. 좌표가 없으면 숙소 연결 구간을 계산하지 않는다.
- 여러 밤 같은 숙소 사용과 밤별 다른 숙소를 모두 표현할 수 있다.
- 외부 페이지를 열기 전에 편집 초안을 보존한다.
- 외부 검색 클릭, 숙소 등록, 사용자의 예약 완료 표시는 서로 다른 상태다. 예약 여부는 자동 확인하지 않는다.

Airbnb 공식 도움말은 위치·여행 날짜·인원으로 검색하는 사용자 기능을 설명한다.
이는 우리 서비스의 예약 API나 조건 전달용 링크 계약이 확인됐다는 뜻은 아니다.
[Airbnb 숙소 검색 안내](https://www.airbnb.com/help/article/479).

**수용 기준:** 숙박일별 검색 기준과 조건을 확인하고 외부로 이동할 수 있으며, 선택한 숙소를 돌아와 일정에 등록할 수 있다.

### F-09. 친구 초대·취향 수집·공동 편집 — P0

**참여**

- 지도와 상세 계획에서 초대 링크를 만들고 사용자가 직접 공유한다.
- MVP의 ‘친구’는 해당 여행에 초대된 참여자다. 전역 친구 검색·친구 관계 그래프는 필요하지 않다.
- 초대자는 회원이어야 하며, 비회원 초안에서 초대를 누르면 로그인 후 초안을 이어간다.
- 초대 링크 열기만으로 참여 처리하지 않는다. 로그인과 초대 수락 후 참여자가 된다.
- 친구는 기존 성향을 이번 여행에 사용하거나 짧은 성향 입력을 할 수 있다.
- 아바타 선택은 이미 참여한 사람을 이번 추첨 일행에 포함하는 행동이다. 아바타 드래그만으로 타인 계정에 초대를 수락시키지 않는다.
- 그룹 크기는 1~8명 제안이며, 초대 대기와 실제 수락 인원을 구분한다.

**취향 반영**

- 응답한 참여자의 취향을 동등하게 반영하고 ‘4명 중 3명 취향 반영’처럼 상태를 표시한다.
- 늦게 참여하거나 성향을 수정한 친구가 있으면 재추천 가능 알림을 표시한다.
- 목적지는 유지하며 재추천 결과를 비교 후 적용한다.
- 그룹에게는 합산 태그와 반영 여부를 기본 공개하고 개인 성향 원문·과거 기록은 자동 공개하지 않는다.
- 탈퇴·제외 시 이후 추천에서 제외한다. 이미 저장된 장소는 자동 삭제하지 않는다.

**권한·충돌**

| 역할 | 가능 행동 |
|---|---|
| 방장 | 편집, 초대·링크 폐기, 참여자 관리, 최종 확정, 여행 삭제 |
| 참여자 | 일정 열람·편집, 본인 취향 수정, 본인 탈퇴 |
| 초대 대기/미참여자 | 최소 초대 정보 확인과 참여 요청만 가능 |

- 변경 시 작성자·시각·버전을 남긴다.
- 같은 버전을 동시에 저장하면 뒤 요청에 충돌 안내와 최신본을 제공하고 자신의 미저장 편집도 보존한다.
- 다른 참여자의 편집을 알림 또는 주기 갱신으로 확인할 수 있게 한다. MVP에서 WebSocket·실시간 커서는 필수가 아니다.
- 방장 탈퇴는 권한 이양 또는 여행 삭제를 먼저 처리한다.
- 초대 링크는 만료·폐기 가능하고, 공유 토큰만으로 편집 권한을 얻지 못한다.

**수용 기준:** 서로 다른 두 계정으로 초대 수락→취향 반영→공동 편집→충돌 복구까지 가능하다. 미참여 계정의 조회·수정 요청은 차단된다.

### F-10. 저장·공유·내 여행 — P0

- 서버 저장에는 로그인과 해당 여행 권한을 요구한다.
- 저장 항목은 목적지, 유입 방식, 기간·날짜, 참여자, 취향 반영 버전, Day별 장소·순서·체류 시간, 식사·메모, 숙소, 경로 상태다.
- 상태는 DRAFT(초안), CONFIRMED(계획 확정)로 구분한다. 여행 완료 기록은 P1이다.
- ‘저장됨/저장 중/미저장/저장 실패’를 명확히 표시한다.
- 비회원은 개인 초안을 임시 보관하되 서버에 영구 저장됐다고 안내하지 않는다.
- 초대 공유와 공개 공유를 구분한다. MVP는 참여자 공유가 기본이며 공개 링크 열람은 P1이다.
- 삭제는 소유 권한 확인 후 대상을 명시하고 확인한다.
- 기존 저장 코스는 Day 1로 표현할 수 있도록 마이그레이션하며 기존 ID·소유자·경유지를 보존한다.

**수용 기준:** 로그인 전후 및 다른 기기에서 서버 저장본이 복원되고, 다른 여행의 ID를 넣어 조회·수정할 수 없다.

## 6. 추천·일정 구성 정책

### 6.1 입력과 결과

입력은 regionId, 일수/날짜, Day별 사용 시간, 이동수단, 참여자별 성향 스냅샷, 필수·제외 장소, 고정 일정이다.
결과는 Day별 실재 장소 ID·순서·체류시간·추천 이유, 이동 계산 상태, 미충족 조건, 알고리즘 버전이다.

지역 추첨 기록과 코스 생성 기록은 별도 ID로 관리한다. 친구 합류로 코스를 다시 만들어도 원래 추첨 결과는 변하지 않는다.

### 6.2 개인과 그룹 선호

1. 선택한 경험 태그를 같은 분류 체계의 정규화된 선호 점수로 변환한다.
2. 장소의 분류·이름·상세 설명에 근거해 태그를 부여한다. 태그 근거와 데이터 버전을 관리한다.
3. 입력한 사람별 선호를 먼저 정규화한 뒤 동등한 가중치로 평균한다. 많이 선택한 사람이 더 큰 영향력을 갖지 않게 한다.
4. 모두 미응답이면 균형형 코스를 만들고 취향 미반영 상태를 표시한다.
5. 그룹 여행 속도는 더 여유로운 응답을 기본으로 삼고 상세 계획에서 공동 조건으로 조정한다.
6. 명시적 제외 조건은 합집합으로 적용한다. 필수 포함과 충돌하면 자동으로 무시하지 않고 해결을 요청한다.
7. 평균 점수만 높이고 특정 참여자를 계속 소외시키지 않도록, 가능할 때 각 응답자에게 맞는 관광지를 전체 여행에 최소 한 곳 포함한다. 불가능하면 이유를 알린다.

### 6.3 코스 생성 순서

1. 선택 지역의 유효한 관광지 목록을 조회한다.
2. 폐쇄·기간 불일치·명시적 제외 조건을 적용하고 좌표 없는 장소는 자동 동선 후보에서 제외한다.
3. 선호 적합도, 장소 다양성, 설명 근거, 이동 부담으로 후보를 평가한다.
4. 가까운 장소를 Day별로 묶되 고정 장소·시간을 먼저 배치한다.
5. 장소 체류, 식사·휴식, 이동을 합산해 하루 사용 시간 안에 구성한다.
6. 자동차 경로 결과가 도착하면 예상 이동을 보정하고 시간 초과를 다시 판정한다.
7. 장소 ID·지역·중복·시간·미지원 구간을 검증하고 초안을 반환한다.

초기 체류시간 기본값은 장소 유형별 운영 설정으로 관리하고 ‘예상 체류시간’으로 표시한다.
시간 예산은 `이동 + 관광 체류 + 식사·휴식 + 여유 시간`이다.
날짜·운영시간이 없거나 지원하지 않는 교통 구간이 있으면 방문 가능 여부가 완전히 검증된 것으로 표시하지 않는다.

후보가 부족하면 짧은 코스와 비어 있는 시간을 보여준다. 장소나 운영시간을 생성형 AI로 만들어 채우지 않는다.
주변 지역 확장은 P1의 명시적 선택 기능으로 남긴다.

### 6.4 생성형 AI 사용 범위

MVP의 필수 결과는 개인화된 실제 장소 조합이다. 생성형 AI 도입 여부가 완료 기준은 아니다.
사용한다면 설명 요약·추천 이유 문장화에 제한하고 입력 데이터 밖의 사실, 예약 가능 여부, 이동시간을 생성하지 않는다.
장소 ID 검증과 템플릿 대체 경로를 유지한다.

## 7. 데이터와 외부 연동

### 7.1 관광지 원천

한국관광공사 국문 관광정보 서비스는 관광·사진 정보와 공통·소개·이미지 등의 조회 기능을 제공한다.
개별 항목의 완전성은 별도 수집·검증이 필요하다.
[한국관광공사 국문 관광정보 서비스](https://www.data.go.kr/tcs/dss/selectApiDataDetailView.do?publicDataPk=15101578).

필수 관리 필드는 원천 content ID, 서비스 지역 ID, 이름, 분류, 주소, 좌표, 이미지, 상세 설명,
운영 정보, 원천 수정일, 수집 시각, 출처·이용 조건, 유효 상태다.
TourAPI 지역 분류와 프로젝트의 SIG_CD를 직접 동일시하지 않고 매핑을 검증한다.

- 상세·이미지는 배치 수집을 기본으로 하고 결과 생성 때 모든 상세 API를 연속 호출하지 않는다.
- 이미지 누락은 대체 카드, 설명 누락은 ‘상세 설명 준비 중’으로 표현한다.
- 삭제·폐쇄된 장소는 새 추천에서 제외하고 기존 일정에는 변경 경고를 남긴다.
- 호출 한도와 비용은 현재 발급 계정·상품 조건을 배포 전에 확인하고 설정값으로 관리한다.
- 지역별 좌표·이미지·설명 확보율과 추첨 가능 여부를 확인하는 운영 리포트를 둔다.
- 관광지 개수가 많다는 이유로 지역 추첨 확률을 높이지 않는다.
- 상세 HTML과 외부 링크는 안전하게 정제한다.

### 7.2 음식점 보류의 의미

기존 코드에는 `FoodPlace`, `GoodPriceShop`과 식당을 넣는 자동 코스가 있다.
따라서 ‘음식점 데이터가 전혀 없다’가 아니라 **품질·위치·최신성·추천 신뢰도를 정리하기 전까지 새 MVP에서 자동 추천을 제외한다**고 정의한다.
기존 데이터와 사용자가 저장한 식당은 유지한다. 신규 기본 생성기만 관광지 중심으로 바꾼다.

재도입 조건은 좌표 확보, 중복·폐업 점검, 출처·이용 범위 확인, 여행 동선에 맞는 후보 커버리지, 사용자 평가다.
후속 도입 시에도 ‘맛집’이라는 품질 보증과 단순 음식점 정보를 구분한다.

### 7.3 외부 시스템 장애

| 장애 | 제품 동작 |
|---|---|
| TourAPI 지연·한도 소진 | 적재된 관광지로 계속 탐색, 누락 상태 표시, 배치 재시도 |
| 카카오 지도 로딩 실패 | Day별 텍스트 일정과 외부 지도 열기 제공 |
| 자동차 경로 실패 | 일정 편집·저장 유지, 해당 구간 확인 필요·재시도 |
| Airbnb 조건 전달 실패 | 검색어·날짜·인원 복사와 서비스 열기 제공 |
| 개인화 계산 실패 | 기존 일정 유지, 동일 조건 재시도 |
| 참여자 취향 미응답 | 응답자만 반영하거나 균형형 초안 제공 |

| 전국 지도 | 250개 구역 지도, 탐색 UI | 메인 진입·랜덤 장치·도착 흐름 재정리 |
| 랜덤 | `RandomRecommendServiceImpl`이 관광지 보유 지역 중 추첨 | 유효 풀, 조건·중복 방지, 멱등성, 연출 연결 |
| 개인화 발견 | 다이어리 기반 공식 코스 후보 | 지역 선택 이후 관광지 조합 개인화로 변경 |
| 하루 코스 | `DayPlanService`의 규칙 기반 하루·반일, 식당 포함 | 취향·그룹·관광지 중심 여러 날 생성 |
| 저장 | `SavedCourse`의 단일 경유지 목록 | Day·체류시간·숙소·공동 소유권·버전 |
| 경로 | `CourseRouteService`의 저장 코스 도로 경로 캐시 | 편집 후 Day별 갱신, 부분 실패, 시간 변경 반영 |
| 공유 | `SharedTripRoom`의 후보·반응·확정 | 로그인 참여, 성향 동의, 공동 편집·권한 |
| 숙소 | 이번 점검의 확인 범위에서 통합 구현 확인 못 함 | 위치 기반 검색 연결·수동 숙소 등록 |
| 이벤트 | 기존 PRD에서 핵심 퍼널 로깅 미구현 | 추첨→계획→저장 연결 이벤트 |
| 보조 기능 | 다이어리·후기·상담·근처 추천 | 유지하되 MVP 필수 여정에서 분리 |

기존 데이터 개수는 [DATA.md](DATA.md)의 기준일과 함께 인용한다. 이번 문서는 과거 수치를 최신 운영 수치로 재사용하지 않는다.

## 11. 성공 지표와 검증

### 11.1 핵심 지표

**랜덤 목적지 계획 확정률**

- 분모: 측정 주간에 랜덤 도착 카드를 실제로 본 고유 사용자/익명 사용자.
- 분자: 그 사용자 중 해당 추첨으로 시작한 여행을 도착 후 7일 이내 확정한 고유 사용자.
- 동일 사용자의 반복 추첨은 분모에서 중복 집계하지 않는다.
- 직접 선택한 여행은 제외하고 별도 집계한다.
- 로그인 전후 식별 연결, 봇·팀 테스트 제외, 미완료 7일 관측 구간을 반영한다.
- 초기 목표값은 파일럿 기준선 확보 후 설정한다. 랜덤 클릭 증가만으로 성공을 판정하지 않는다.

### 11.2 보조 지표

| 목적 | 지표 |
|---|---|
| 온보딩 부담 | 완료율, 완료 시간, ‘모르겠어요’ 비율 |
| 랜덤의 매력 | 첫 도착→여행 시작률, 재추첨 수, 결과 후 이탈률 |
| 실행 가능성 | 생성 성공률, 계획 확정까지 시간, 시간 초과·경로 미확인 비율 |
| 개인화 | 취향 반영 체감, 추천 장소 유지율, 교체 이유 |
| 함께 계획 | 초대 수락률, 성향 응답률, 2명 이상 편집 여행 비율 |
| 숙소 연결 | 외부 검색 클릭률, 숙소 수동 등록률 |
| 재사용 | 저장 여행 재열람, 여행 날짜 전후 재열람 |
| 새로움 | ‘평소 고르지 않았을 지역’ 응답 비율, 선택형 방문 이력 기준 미방문 선택률 |
| 분산 | 추첨/선택/확정 단계별 고유 지역 수, 상위 10개 지역 점유율, 추첨 제외 지역 수 |
| 방문 | P1의 여행 후 자기보고. 실제 방문의 독립적 증명과 구분 |

지역 확률이 균등해도 최종 방문은 편중될 수 있다. 노출·선택·방문을 따로 평가한다.
숙소 클릭은 예약이나 지역 소비가 아니다.

### 11.3 최소 이벤트

`onboarding_completed`, `random_requested`, `random_result_viewed`, `random_redrawn`,
`trip_started`, `course_generated`, `course_generation_failed`, `plan_saved`,
`invite_accepted`, `member_preference_submitted`, `plan_edited`, `route_failed`,
`stay_search_opened`, `stay_added`, `plan_confirmed`, `plan_reopened`.

이벤트에는 ID·세션·drawId·tripId·지역·참여 인원·알고리즘 버전 등 필요한 연결 값만 담고 성향 원문·주소·초대 토큰은 넣지 않는다.
재전송 이벤트는 ID로 중복 제거한다. 전체 지도 렌더를 250개 지역의 실제 노출로 기록하지 않는다.

### 11.4 사용자 검증 제안

- 페르소나에 맞는 10~15명과 3~5개 친구 그룹으로 무도움 사용성 테스트를 진행한다.
- ‘왜 유명 지역을 반복 선택했는지’ 최근 행동을 확인한다.
- 다트/대포 시안을 비교해 이해도·재미·반복 피로·모바일 조작을 평가한다.
- 같은 지역에서 일반 코스와 취향 코스를 비교하고 장소 선택 이유를 확인한다.
- 그룹 테스트에서는 한 친구의 늦은 참여, 서로 다른 성향, 동시 저장을 포함한다.
- 성공 판정은 실제 과제 완료와 만족도 기준선을 먼저 확보한 뒤 정한다.
- 지역 분산과 소상공인 효과는 후속 현장·방문·소비 자료로 검증한다.

## 13. 개발 순서와 범위 관리

달력 일정은 팀 인원과 가용 시간을 확인한 뒤 산정한다. 아래는 의존성을 따른 실행 순서다.

| 단계 | 작업 | 완료 산출물 |
|---|---|---|
| 1. 기획·데이터 기준 | 성향 항목, 추첨 풀, Day·권한 모델, 지역 데이터 품질 확인 | 화면 흐름, 스키마·마이그레이션안, 추첨 커버리지 |
| 2. 혼자 발견 | 온보딩→지도→랜덤→도착→여행 조건 | 혼자 이용 가능한 연속 흐름 |
| 3. 계획 | 개인화 관광지 조립, 여러 Day, 수정·저장, 경로 갱신 | 관광·식사 시간·동선이 있는 다일 계획 |
| 4. 함께 계획 | 초대·성향 동의·그룹 추천·공동 편집·충돌 | 두 계정 이상 공동 사용 검증 |
| 5. 여행 준비 | 숙소 검색·등록·전후 동선, 내 여행·확정 | 다시 열어 사용할 수 있는 일정 |
| 6. 출시 검증 | 대표 연출 완성, 접근성, 장애·권한·마이그레이션·퍼널 검증 | P0 수용 결과와 사용자 테스트 보고 |

랜덤 연출 시안은 단계 1~2와 병행하고 결과 계약이 확정되면 연결한다.

**P1:** 음식점 데이터 검증 후 추천, 읽기 전용 공개 공유, 여행 후 기록, 전역 친구 목록,
사용자가 동의한 인접 지역 확장, 보다 나은 비자동차 계획, 실시간 공동 편집 강화.

**P2:** 개인화 모델 학습, 예약 제휴, 지역 사업자 연계, 방문·소비 기반 분산 효과 분석.
음식점 데이터 정비나 대포의 고급 물리 연출 때문에 Day별 계획·친구 취향·숙소 연결을 MVP에서 빠뜨리지 않는다.

## 14. 주요 리스크와 대응

| 기존 기능과 새 흐름 충돌 | 기존 저장·공유 데이터 유지, 신규 핵심 진입만 전환, 호환 점검 |

## 15. 회의·발표용 제품 설명

> 숨은여행은 유명한 곳만 반복해서 가는 데 지친 여행객을 위한 국내 여행 서비스입니다.
> 여행 취향을 입력하고 전국 250개 구역 지도에서 랜덤 버튼을 누르면 예상하지 못한 지역에 도착합니다.
> 그 지역으로 떠나기로 하면 나와 친구의 취향을 반영해 실제 관광지로 코스를 만들고,
> Day별 일정과 이동 동선을 함께 편집하며 주변 숙소 검색까지 이어갈 수 있습니다.
